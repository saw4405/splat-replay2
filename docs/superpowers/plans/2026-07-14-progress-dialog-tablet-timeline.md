# 進捗ダイアログ 900×720タイムライン同時表示 実装計画

> 承認済み設計: `docs/superpowers/specs/2026-07-14-progress-dialog-tablet-timeline-design.md`

**目的:** 900×720の縦型工程レイアウトで、現在のプレビューとタイムライン1段をスクロールなしで同時表示する。

**方針:** 既存DOMと進捗状態は変えず、900px以下では非アクティブなタイムライン行を隠す。641～900pxでは編集モニターを高さ制約付きグリッドにし、16:9プレビューだけを可変高にする。

**対象:** Svelte / CSS / Playwright。API・バックエンド・永続データは変更しない。

## Task 1: 900×720の表示契約をE2Eへ追加

**変更ファイル:** `frontend/tests/e2e/responsive-layout.spec.ts`

1. 900px境界ケースで、処理中タイムラインを識別できる進捗イベントを送る。
2. プレビューと現在タイムラインの矩形が、スクロール位置0の進捗本文表示領域内に収まることをassertする。
3. 後続タイムラインが表示されないことをassertする。
4. 変更前に対象E2Eを実行し、タイムライン収容のassertが失敗することを確認する。

## Task 2: タブレット縦型工程の高さ配分を実装

**変更ファイル:** `frontend/src/main/components/progress/ProgressDialog.svelte`

1. 900px以下で非アクティブなタイムライン行を表示領域から除外する。
2. 641～900pxの編集中パネルを画面高に収める。
3. 編集モニターをメタデータ・可変高プレビュー・現在タイムラインのグリッドにする。
4. プレビューの16:9とタイムラインの既存情報量を維持する。
5. 901px以上と640px以下の既存規則を上書きしないことを確認する。

## Task 3: 対象検証

1. `task.exe format:check` を実行する。
2. `task.exe test:frontend:component` を実行し、既存の進捗表示契約を確認する。
3. `task.exe test:workflow:smoke` を実行し、900 / 901 / 320pxの導線を確認する。

## Task 4: 視覚確認と全体ゲート

1. 900×720で実画面を表示し、実動画プレビューと現在タイムラインをキャプチャする。
2. 横overflow、プレビュー比率、タイムラインの欠け、フッターとの重なりを確認する。
3. `task.exe verify` を実行する。
4. `git diff` で対象外の変更を混入させていないことを確認する。
