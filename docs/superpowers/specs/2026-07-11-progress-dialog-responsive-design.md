# 進捗ダイアログ レスポンシブ対応設計

## 目的

進捗ダイアログを幅320px以上のスマートフォン、タブレット、デスクトップで利用可能にする。狭幅時は現在処理中の工程だけを大きく表示し、ほかの工程は横幅を予約しないコンパクトな見出しとして残す。

## 現状

- `ProgressDialog` は編集・待機・アップロードを常時横並びで表示する。
- 待機パネルは300px、アップロード展開時は最小280px、YouTubeパネル展開時は最小320pxを要求する。
- `ProgressDialog` 内にはレスポンシブ規則がなく、本文とパイプラインは `overflow: hidden` である。
- 共通 `BaseDialog`、`SettingsDialog`、`MetadataForm` は900px相当をダイアログ系のレイアウト切替に使用している。
- アプリの明示的な最小幅は320pxで、E2Eは320、375、667、768、1024、1920px幅を使用している。

## 決定

### ブレークポイント

- 900px超: 現在の3列レイアウトを維持する。
- 900px以下: 工程フォーカス型の縦レイアウトへ切り替える。
- 640px以下: 進捗ダイアログだけを画面全体へ広げ、タッチ操作向けに余白とフッターを再配置する。

900pxはアプリ全体の共通トークンではなく、進捗ダイアログ固有の content-driven breakpoint とする。CSS表記は既存ダイアログに合わせて `56.25rem` を使う。

### 現在工程の選択

レスポンシブ表示用の工程は `editing | waiting | uploading` の3値とし、次の優先順位で選ぶ。

1. アップロードが実行中・失敗・成功なら `uploading`
2. 編集が実行中・失敗なら `editing`
3. 編集済み動画が1件以上待機していれば `waiting`
4. それ以外は `editing`

アップロードと編集が同時実行中の場合は、既存UIの展開規則と合わせてアップロードを優先する。失敗した工程は折り畳まず、原因を確認できる状態を維持する。

### 狭幅レイアウト

- DOM順序は「編集 → 待機 → アップロード」のまま維持する。
- 現在工程は詳細内容を表示し、利用可能な横幅をすべて使う。
- 非アクティブ工程は高さ44px以上の1行見出しとし、アイコン・番号・工程名だけを表示する。
- 手動の工程切替は追加しない。処理状態に応じて自動更新する。
- `aria-current="step"` で現在工程を公開する。
- 横並びパネル間を前提とするアップロード飛行アニメーションは900px以下で非表示にし、受信グリッドと進捗バーは維持する。

### スマートフォン外枠

`BaseDialog` に既定値 `false` の `mobileFullscreen` オプションを追加し、`ProgressDialog` だけが有効化する。

- 640px以下ではoverlay余白をなくし、ダイアログを `100dvh` にする。
- ヘッダーとフッターは縮まず、本文だけを縦スクロールさせる。
- スマートフォンでは角丸を外し、利用可能な横幅を確保する。
- フッターを2段へ変更し、操作ボタンの最小高さを44pxにする。
- 接続警告と再接続ボタンは折り返しを許可する。
- `mobileFullscreen` を指定しない既存ダイアログの動作は変更しない。

## テスト方針

`docs/test_strategy.md` をSSoTとする。

- 変更分類: logic + component + workflow
- logic: 工程選択の優先順位を純粋関数で検証する。
- component: 各工程に付く `aria-current="step"` の意味契約を検証する。
- workflow: 900pxと901pxの境界、320pxの画面内収容、横overflow、本文スクロール、フッター到達性をPlaywrightで検証する。
- CSS文字列や内部class名はassertしない。
- integration、contract、performanceテストは、境界契約・複数コンポーネント連携・時間予算を変更しないため追加しない。

## 受入基準

1. 901px以上では現行3列表示が維持される。
2. 900px以下では現在工程だけが詳細表示され、非アクティブ工程は1行見出しになる。
3. 320px幅で横スクロールが発生せず、すべての工程見出しとフッター操作へ到達できる。
4. 現在工程が処理状態および失敗状態に追従する。
5. 既存の進捗イベント、動画プレビュー、待機カード、アップロード再構成表示の振る舞いを変更しない。
6. 既存の未コミット変更を保持し、この対応と無関係なファイルを変更しない。

## 対象外

- アプリ全体のブレークポイントトークン新設
- ほかのダイアログのスマートフォン表示変更
- 手動タブ・スワイプ・アコーディオン操作
- 既存テーマ色やアニメーションデザインの全面変更
