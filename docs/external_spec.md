# Splat Replay - 外部設計書

## 1. 目的

Windows 11 PC または Apple Silicon 搭載 Mac でスプラトゥーン 3 のプレイ映像を録画・確認し、
必要に応じて編集・アップロードまで行える環境を提供する。

本アプリは、セットアップ、録画、メタデータ管理、編集、アップロードの導線を一体で提供し、
プレイヤーが試合の振り返りと共有を行いやすくすることを目的とする。

## 2. スコープ

| 項目         | 内容                                             |
| ------------ | ------------------------------------------------ |
| 対象ユーザ   | 個人プレイヤー                                   |
| 主な利用目的 | ① 録画と振り返り ② YouTube などへの共有          |
| 対応ゲーム   | スプラトゥーン 3                                 |
| 対応 OS      | Windows 11 64bit、Apple Silicon 搭載 macOS       |
| 主な外部連携 | HDMI / USB / OBS Studio / NDI / YouTube API / Groq API |

macOS 版は Apple Silicon のみを対象とします。配布 DMG 内の `.app` は固定の自己署名証明書で署名し、公証しません。

## 3. システム境界と責務分担

### 3.1 システム境界

外部設計上のシステム境界は `本アプリ` のみを内側とし、
利用者、ハードウェア、外部ソフトウェア、外部サービスはすべて境界の外側に置く。

```mermaid

        NDI[DistroAV / NDI Runtime]
        FFmpeg[FFmpeg]

    subgraph Inside[システム境界内]
```

- `GUI` や `Web API` は、本アプリが利用者へ提供する接点として扱う。
- `OBS Studio`、`DistroAV / NDI Runtime`、`FFmpeg`、`Tesseract`、`Groq`、`YouTube` は、本アプリが利用する外部要素として扱う。

| 主体                      | 担う責務                                                                                       | 担わない責務                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |

- ゲーム映像そのものの生成

- 外部サービス障害や認証ポリシー変更の恒久解消

## 6. 機能要件

### 6.1 起動と画面遷移

- 起動時にセットアップ履歴と録画・判定・編集・YouTube アップロードに必要なソフトウェアおよび保存設定を確認し、判定中はローディング画面を表示する。
- 初回セットアップ未完了、または既存環境に必須項目の不足がある場合は、通常画面と自動録画を開始せず、セットアップ画面に不足項目と修復先を表示する。
- 既存環境はセットアップ履歴を保持し、不足している項目だけを修復できること。
- この起動時判定は Web GUI / WebView 起動後の最初の自動録画開始前に行う。自動録画開始後の再判定と CLI `auto` の開始判定は対象外とする。
- Switch の電源 OFF、キャプチャデバイスの一時切断、入力された PC 要件、一時的なネットワーク障害は起動時の必須ソフト・保存設定検査の不足として扱わない。
- 必須項目がそろった場合はメイン画面を表示する。
- Web GUI と WebView GUI は同一の画面構成で動作する。

### 6.2 セットアップ

- セットアップウィザードで以下の手順を順次実行できること。
  - ハードウェア確認
  - FFmpeg セットアップ
  - OBS セットアップ
  - Tesseract セットアップ
  - サムネイル用フォント確認（OS 標準フォントで代替可能）
  - 文字起こし設定
  - YouTube API 設定
- 専用フォントがない場合は OS 標準フォントを利用できること。文字起こしを無効にした場合、文字起こし用マイク・API キー・FLAC は必須としない。
- 起動時に必要ソフトウェアと保存設定を再検査し、不足項目を個別に修復できること。
- 初回セットアップと必須項目の修復が完了するまでメイン画面および自動録画を開始しないこと。

### 6.3 録画準備

- キャプチャデバイスの接続状態を確認し、未接続の場合は利用者へ案内を表示する。
- キャプチャデバイスは保存した表示名で識別し、同じ表示名の機器を継続して利用できること。
- OBS の起動状態を確認し、未起動の場合は起動する。
- OBS の仮想カメラを有効化する。
- ローカルプレビューは 1920×1080・60 FPS を要求する。取得可能な解像度・フレームレートは機器や OS の実装に従う。
- プレビュー入力種別を取得できること。
  - `live_capture`
  - `video_file`

### 6.4 録画制御

```mermaid
stateDiagram-v2
    [*] --> 待機
    待機 --> 自動録画中 : 自動録画有効化 / 開始条件成立
    待機 --> 手動録画中 : 手動録画開始
    自動録画中 --> 録画済保存 : 停止条件成立
    手動録画中 --> 一時停止中 : 一時停止
    一時停止中 --> 手動録画中 : 再開
    手動録画中 --> 録画済保存 : 停止
    録画済保存 --> 待機
```

- 自動録画の有効化・無効化ができること。
- 手動で録画の開始・一時停止・再開・停止ができること。
- 録画状態を取得し、GUI に表示できること。
- 最新プレビューフレームを取得し、GUI に表示できること。
- 録画中のリアルタイムメタデータを取得・更新できること。
- 録画停止後は、録画済データとして動画と関連メタデータを保存すること。
- Switch 電源 ON 後に OBS 音量の観測を始め、無音の結果が続く待機中だけ観測を継続すること。無音以外の結果、またはマッチング開始で観測を終了する。
- 無音以外の結果を確認した後は、同じ Switch 電源 ON 周期で音声観測を再開しないこと。無音を理由に OBS を再起動しないこと。
- サーモンランの自動録画は現状未対応とする。

### 6.5 編集・アップロード

- 録画済データ一覧と編集済データ一覧を表示できること。
- 録画済データに対して以下の操作ができること。
  - 動画再生
  - サムネイル拡大表示
  - メタデータ編集
  - 字幕編集
  - 削除
- 編集済データに対して以下の操作ができること。
  - 動画再生
  - サムネイル拡大表示
  - 削除
- メイン画面から編集・アップロード処理を手動開始できること。
- 初回の手動処理開始前に、YouTube 権限ダイアログを表示できること。
- アプリ起動時は未処理の録画済データと編集済データを検出して保持し、編集・アップロードを自動開始しないこと。
- `電源オフ後に編集開始する` が有効で、録画済データが存在する場合は、電源 OFF 検知後に自動処理開始予告を表示し、一定時間経過後に編集・アップロードを開始できること。
- 編集・アップロード処理中は進捗状態を取得・表示できること。
- 編集中・アップロード中にキャンセルを要求でき、実処理の停止確認までは中断中として表示すること。YouTube アップロードは 16 MiB のチャンク境界でキャンセルを確認すること。
- キャンセル時は、編集成果物の確定前なら元録画を、確定後なら編集済み動画を保持すること。キャンセルされた実行が残存ファイルを理由に自動再開しないこと。
- 動画編集時に以下を実行できること。
  - 編集対象動画の結合
  - タイトル・説明・チャプターの生成
  - 字幕の結合
  - 音量調整
  - サムネイル生成
- アップロード時に以下を実行できること。
  - YouTube への動画アップロード
  - タイトル・説明・タグ・公開範囲の反映
  - 字幕の付与
  - プレイリスト追加
- 録画は MKV で保持する。アプリ内再生では MKV に対して一時 MP4 を用意し、MP4 は変換せずそのまま使うこと。
- 実行中の編集・アップロード処理に対して、今回の処理に限った `sleep_after_upload` の一時設定を更新できること。

### 6.6 設定

- GUI からアプリケーション設定を取得・更新できること。
- 設定は少なくとも以下のカテゴリを扱えること。
  - キャプチャデバイス
  - OBS 接続
  - 動画保存先
  - 動作設定
  - 文字起こし設定
  - 動画編集設定
  - YouTube アップロード設定
  - WebView 表示設定
- カメラ権限ダイアログおよび YouTube 権限ダイアログの表示済状態を保持できること。
- macOS の YouTube OAuth 認証情報は Keychain に保存すること。OAuth クライアントファイルは設定フォルダに置く。

### 6.7 スリープ

- `アップロード終了後にスリープする` が有効な場合、編集・アップロード完了後にスリープ開始予告を表示できること。
- スリープ開始予告はカウントダウン付きで表示し、利用者がキャンセルできること。
- 条件成立時に Windows PC または Mac をスリープできること。
- macOS では OS の `pmset sleepnow` を使ってスリープを要求すること。

## 7. 非機能要件

- **使用感** : セットアップ完了後は 1 つのメイン画面で録画状態確認、録画制御、録画済データ確認、編集・アップロード開始、設定変更を行えること。
- **操作継続性** : 自動録画、自動処理開始予告、スリープ開始予告の状態を GUI 上で継続して確認できること。
- **暫定** : 性能目標の厳密な数値は本書では固定せず、詳細は別途性能評価で扱う。

## 8. ユースケース

### 8.1 初回セットアップ

初回起動時またはセットアップ未完了時に、利用者はセットアップウィザードを完了してメイン画面へ遷移する。

```mermaid
stateDiagram-v2
    [*] --> 起動 : アプリ起動
    起動 --> セットアップ画面 : 未完了
    セットアップ画面 --> セットアップ画面 : 各手順を実施
    セットアップ画面 --> メイン画面 : セットアップ完了
    メイン画面 --> [*]
```

### 8.2 通常録画

セットアップ完了後にメイン画面を開き、録画準備と自動録画を行いながら、必要に応じて手動録画操作やメタデータ修正を行う。

```mermaid
stateDiagram-v2
    [*] --> メイン画面 : アプリ起動
    メイン画面 --> 録画準備 : 準備開始
    録画準備 --> 自動録画 : 準備完了
    自動録画 --> 録画済データ保存 : 停止条件成立
    自動録画 --> 手動操作 : 利用者操作
    手動操作 --> 自動録画
    録画済データ保存 --> メイン画面
```

### 8.3 編集・アップロード

録画済データの確認後、利用者がメイン画面から処理開始するか、設定に応じて電源 OFF 検知後の自動処理を利用する。

```mermaid
stateDiagram-v2
    [*] --> 録画済データあり
    録画済データあり --> 手動開始 : 利用者が処理開始
    録画済データあり --> 自動開始予告 : 電源OFF検知かつ自動処理有効
    自動開始予告 --> 編集アップロード中 : カウントダウン完了
    手動開始 --> 編集アップロード中
    編集アップロード中 --> 完了
    完了 --> スリープ予告 : スリープ有効
    完了 --> [*] : スリープ無効
    スリープ予告 --> [*]
```

## 9. 設定

現行実装で扱う代表設定は以下のとおり。

| カテゴリ             | 代表項目                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------ |
| キャプチャデバイス   | キャプチャボード名                                                                         |
| OBS 接続             | WebSocket ホスト / ポート / パスワード / OBS 実行ファイルパス                              |
| 動画保存先           | 動画保存先フォルダ                                                                         |
| 動作                 | `電源オフ後に編集開始する` / `アップロード終了後にスリープする` / `対戦履歴を累積記録する` |
| 文字起こし           | 有効 / 無効、マイクデバイス、Groq API キー、音声認識モデル、言語                           |
| 動画編集             | 音量倍率、タイトルテンプレート、説明テンプレート、チャプターテンプレート、字幕読み上げ設定 |
| YouTube アップロード | 公開範囲、タグ、プレイリスト ID、キャプション名                                            |
| 表示                 | WebView 描画モード                                                                         |

### 9.1 テンプレート設定例

- タイトルテンプレート: `{BATTLE}({RATE}) {RULE} {WIN}勝{LOSE}敗 {DAY} {SCHEDULE}時～`
- 説明欄テンプレート: `{CHAPTERS}`
- チャプターテンプレート: `{RESULT} {KILL}k {DEATH}d {SPECIAL}s  {STAGE}`

## 10. UI

### 10.1 CUI

- `auto` コマンドで録画から編集・アップロードまでの全自動処理を実行できること。
- `upload` コマンドで編集・アップロード処理を実行できること。
- `web` コマンドで Web GUI を起動できること。
- `webview` コマンドで pywebview ベースのデスクトップ GUI を起動できること。

### 10.2 GUI

GUI はセットアップ画面とメイン画面の 2 画面で構成する。

#### 10.2.1 セットアップ画面

- セットアップウィザードを表示できること。
- 現在のセットアップ手順に応じた画面を切り替えられること。
- 手順の進行状況を保持し、完了後にメイン画面へ遷移できること。

#### 10.2.2 メイン画面

- 設定画面を起動できること。
- ゲーム映像をプレビュー表示できること。
- 録画状態を表示できること。
- 手動で録画開始・一時停止・再開・停止ができること。
- リアルタイムメタデータを表示し、更新できること。
- 録画済データ一覧を表示し、動画再生、サムネイル拡大、メタデータ編集、字幕編集、削除ができること。
- 編集済データ一覧を表示し、動画再生、サムネイル拡大、削除ができること。
- 編集・アップロード処理の開始ボタンを表示できること。
- 編集・アップロード処理の進捗ダイアログを表示できること。
- 自動処理開始予告およびスリープ開始予告を通知できること。
- macOS の通知名は「Splat Replay」とし、表示には macOS の通知許可を使うこと。
- 設定ダイアログで設定変更できること。
- macOS でウィンドウを閉じた場合はアプリを終了せず、メニューバーから画面を再表示または完全終了できること。
- macOS のメニューバー常駐アイコンは処理状態を示し、アプリアイコンの左下に状態記号を重ねて表示すること。

> **UX 指針** : 主要操作は 1〜2 クリック以内で完結し、リアルタイム反映されること。
