# 外側スプラッシュを廃止し起動中の円を常時回転させる

- ID: 20260910-072430
- 状態: accepted
- 日時: 2026-09-10T07:24:30+09:00
- 判断者: 共同

## 目的・問題

Windows 配布用 EXE で、実際の pywebview アプリウィンドウが目標の 3 秒以内に表示されるなら、先行する PyInstaller bootloader splash をなくし、起動表示を一段にする。

また、アプリ内の起動画面にある円が停止していたため、利用者が起動処理の継続を視覚的に確認できるよう、円を回転させる。

## 前提・制約

- 実行開始からアプリ画面表示までの努力目標 1 秒、目標 3 秒以内という既存要件は維持する。
- 計測対象は単なる最初の可視 Window ではなく、Windows UI Automation で識別したトップレベルの `Splat Replay` pywebview Window とする。
- PyInstaller の `console=False`、Windows GUI サブシステム、pywebview のインライン起動画面、backend の別プロセス並行起動、ready 後の同一 Window への `load_url` を維持する。
- backend の早期終了、起動中 close、callback 例外時のエラー表示と process cleanup を維持する。
- 起動中の円は、Windows のクライアント領域アニメーション設定が無効でも回転させるというユーザーの明示要件を優先する。
- 計測値は実行環境や WebView2 の debug 接続負荷で変動し得る。記録値は保証値ではなく、今回の実測結果である。

## 判断

1. PyInstaller の `Splash` target、`splash.binaries`、`pyi_splash` helper、pywebview Window の `shown` event による splash close 登録を削除する。起動時に表示するアプリ固有画面は、pywebview のインライン起動画面だけとする。
2. インライン起動画面の円には `spin` animation を常時適用する。`prefers-reduced-motion` によって animation を停止する規則は、この起動中表示には適用しない。
3. `console=False`、backend の並行起動、ready 後の `load_url`、起動失敗表示、close/cancel と process cleanup、起動指標の分離は変更しない。
4. backend 初期化の大規模な遅延ロード、backend の同一プロセス化または thread 化は引き続き行わない。

## 検討した選択肢と棄却理由

### PyInstaller bootloader splash と pywebview 起動画面の二段表示を維持する

Python/UI runtime の読み込み中から最も早く可視応答を出せる。しかしトップレベル Window の再計測で、外側 splash は 0.239 秒、実際の `Splat Replay` Window は 1.608 秒（集計値 1.614 秒）で表示され、アプリ画面自体が 3 秒目標内だった。ユーザーもこの条件なら splash は不要と明示したため、冗長な二段表示を維持しない。

### 外側 splash を廃止し、pywebview のインライン起動画面を維持する

起動表示を一段にしながら、約 9 秒を要した実績のある backend ready 待機中も無表示に戻さずに済む。スプラッシュなしの新 EXE でも `Splat Replay` Window を 1.308 秒で確認し、debug 接続を有効にした重い別回でも 2.935 秒だったため採用した。

### インライン起動画面も廃止し、backend ready 後に本画面だけを表示する

以前の無表示時間を再導入し、backend 並行起動と早期フィードバックの目的を失う。ユーザーが不要としたのはアプリ画面より前に出る外側 splash であり、backend 待機中のアプリ内起動画面の廃止は求めていないため採用しなかった。

### OS のアニメーション抑制設定に従って円を停止する

従来 CSS の `prefers-reduced-motion` 停止規則を維持できる。しかし実機では Windows `SystemParametersInfo(SPI_GETCLIENTAREAANIMATION)` が false で、その条件により円が停止していた。ユーザーは停止状態を指摘したうえで「ぐるぐるするようにして」と訂正・明示したため、この起動中の円については採用しなかった。

### OS 設定に応じて別の静的な進捗表現を追加する

アニメーション抑制と進捗表示を両立し得るが、新しい表示仕様とユーザー判断を要する。今回は円を回すという確定要件を超えるため採用しなかった。

## 適用範囲

- Windows の PyInstaller 配布用 EXE における bootloader splash の有無。
- pywebview インライン起動画面の円の animation 規則。
- 既存 ADR `20260909-201235` の判断 2 と、bootloader splash の採用を前提とする記述。

## 適用しない範囲

- PyInstaller の `console=False` と Windows GUI サブシステム。
- pywebview インライン起動画面そのもの、backend の並行起動、ready 後の `load_url`。
- backend 早期終了、timeout、起動中 close、callback 例外時の処理と終了時 cleanup。
- 初回表示、backend ready、本画面操作可能を分離する性能指標。
- backend の初期化内容、プロセス境界、live/replay profile。
- 起動画面以外の animation とアクセシビリティ方針。

## 期待する効果

- 3 秒以内に表示できるアプリ画面の前に、別 toolkit の外側 splash を挟まない。
- 起動表示が pywebview Window の一段だけになり、表示切替と bootloader splash 用コード・バイナリを減らせる。
- 起動中の円が実際に回転し、処理継続を利用者へ示す。
- 既存の backend readiness、失敗処理、cleanup の安全境界を保つ。

## 受け入れる欠点・リスク

- bootloader splash の 0.239 秒という最速の可視応答は失われ、アプリ固有の初回表示は pywebview Window の起動時間に依存する。
- 今回の通常計測 1.308 秒は努力目標 1 秒には届いていない。
- debug 接続を有効にした重い計測は 2.935 秒で、3 秒目標への余裕が小さい。別端末やコールド起動で 3 秒を超える可能性は未確認である。
- 起動中の円は OS のアニメーション抑制設定に従わない。動きを抑えたい利用者への代替表示は今回設けない。
- `animationName` と `animationPlayState` だけでは視覚的な回転を証明しないため、250 ms 間隔で transform 行列が変化したことも実測根拠に含める。

## 再検討条件

- 代表的な Windows 端末の配布用コールド起動で、`Splat Replay` Window が継続して 3 秒を超える場合。
- 本画面を 3 秒以内に操作可能にすることが必須要件になった場合。
- pywebview Window 表示前の無表示が利用継続を妨げ、外側 splash の再導入以外も含めた比較が必要になった場合。
- 起動中の常時 animation が、利用者の健康、安全、アクセシビリティ上の問題になると確認された場合。
- backend のプロセス境界や初期化順序を別目的で再設計する場合。

## ユーザー発言の原文

外側 splash の不要条件と、起動画面の円が停止している問題を示した原文:

> このスピードでアプリ画面が表示されるなら、スプラッシュ画面はいらない。
> また、アプリ画面が表示された最初の表示でぐるぐるしない

メインエージェントは二行目を「ぐるぐるを削除する」と逆に解釈した。ユーザーが意図を訂正した原文:

> ○がぐるぐるしないから、ぐるぐるするようにして

訂正を受け、メインエージェントが受諾内容と判断条件を確認した原文:

> 承知しました。先ほどは逆に受け取っていました。円が止まっている原因は、Windows の「アニメーションを無効化」設定に合わせて CSS が回転を止めていたためです。ご要望を優先し、その停止条件だけ削除して常に回るようにします。スプラッシュ要否は引き続き、実アプリウィンドウの表示時刻で判断します。

実アプリ Window の計測後、外側 splash の削除と円の回転を確定した原文:

> 実測できました。外側スプラッシュは **0.24秒**、実際の「Splat Replay」アプリウィンドウは **1.61秒**で表示されており、3秒以内です。したがってご指定の条件を満たすため、外側スプラッシュは削除し、アプリ最初の画面だけを表示します。その円は常に回転するように直します。既存ADRを変更する判断なので、設計契約に従って整合確認だけ行います。
