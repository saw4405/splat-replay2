# 録画タブの表示区分をAPIの編集可能設定に合わせる

- ID: 20260811-111359
- 状態: accepted
- 日時: 2026-08-11T11:13:59+09:00
- 判断者: ユーザー

## 目的・問題

録画タブの視認性改善を記録した ADR `20260810-174636` は、「キャプチャデバイス／OBS接続／録画／文字起こし」の既存4区分を前提としていました。しかし実装・実画面・APIを照合すると、`record` / `RecordSettings` はユーザー編集向けに公開されておらず、現在表示される正しい区分は「キャプチャデバイス／OBS接続／文字起こし」の3区分でした。

誤った4区分前提へ実装を合わせて設定公開範囲を広げることなく、現行の公開契約と設計記録を一致させます。同時に、採用済み ADR の履歴と当時の原文は保持します。

## 前提・制約

- `frontend/src/main/components/settings/grouping.ts` の録画タブは `capture_device`、`obs`、`record`、`speech_transcriber` の候補 ID を持ちますが、存在しない区分または編集可能フィールドがない区分を表示から除外します。
- `backend/src/splat_replay/infrastructure/adapters/storage/settings_repository.py` では `user_editable` の既定値は `false` です。
- `backend/src/splat_replay/domain/config/record.py` の `RecordSettings` 各項目には `user_editable=True` の指定がありません。
- 記録対象の親会話で確認された実画面 DOM と `/api/settings` の表示結果は3区分です。
- `frontend/tests/e2e/responsive-layout.spec.ts` は「キャプチャデバイス／OBS接続／文字起こし」の3区分を確認する内容で、対象テスト 1/1 の通過が親会話に記録されています。
- 旧 ADR は `accepted` であり、直接修正または削除しません。
- 今回は設定ダイアログの視認性改善に伴う記録訂正であり、新しい設定項目の公開判断は行いません。

## 判断

録画タブは、API が公開するユーザー編集可能な既存区分だけを、単一面の中に区分と行区切りを置く構造で表示します。

現在の正しい表示区分は次の3区分です。

1. キャプチャデバイス
2. OBS接続
3. 文字起こし

`record` / `RecordSettings` は今回新規公開せず、設定公開範囲を変更しません。候補 ID が存在することを、その区分が常に画面へ表示される契約とはみなしません。

この判断は旧 ADR の4区分に関する箇所だけを部分置換し、狭幅リフロー、多重面の簡素化、推奨表示、Boolean 状態文言、スクロール手掛かり、内容適応高さ、ARIA タブ契約など、旧 ADR のその他の視認性判断を維持します。

## 検討した選択肢と棄却理由

### APIが公開する編集可能区分だけを表示する

現在の設定公開境界を変えず、実装、実画面、API、E2E と一致します。視認性改善の目的から逸脱せず、誤った前提だけを正せるため採用しました。

### `RecordSettings` をユーザー編集向けに公開して4区分へ合わせる

旧 ADR の記述とは一致しますが、内部設定を新たに UI 公開する別の設計判断になります。どの値を公開するか、既存キャプチャデバイス設定との重複をどう扱うかも未決定で、今回の視認性改善の範囲を超えるため採用しませんでした。

### 旧ADRを直接修正または削除する

当時の判断、誤認、訂正に至った経緯とユーザー原文を失い、採用済み ADR の不変契約にも反するため採用しませんでした。

### 4区分表現を残して実装との差異だけを注記する

現在有効な判断が二義的になり、将来の実装で `record` を意図せず公開する危険が残るため採用しませんでした。

## 適用範囲

- 録画タブへ表示する区分の選択契約。
- 現在表示する3区分の名称。
- 旧 ADR `20260810-174636` にある4区分前提の節単位の部分置換。
- `record` / `RecordSettings` を今回の視認性改善では新規公開しない境界。

## 適用しない範囲

- `RecordSettings` の各項目を将来公開するかどうかの一般的な判断。
- API の `user_editable` 契約自体の変更。
- 旧 ADR にある4区分以外の視認性判断。
- 設定カテゴリの5タブ構成、録画タブの単一面、行区切りという視覚構造。
- コードまたはテストの追加変更。

## 期待する効果

- 設計記録、API の公開境界、実画面、E2E の区分が一致します。
- 録画タブで、現在ユーザーが編集できる主要3区分と項目の関係を把握しやすくなります。
- 誤った旧 ADR を根拠に `record` / `RecordSettings` が意図せず UI 公開されることを防ぎます。
- 旧 ADR の視認性判断とユーザー原文を履歴として保持しながら、現在有効な区分判断を一意にたどれます。

## 受け入れる欠点・リスク

- 旧 ADR 単体には4区分の記述が残るため、現在有効な判断を知るには本 ADR の部分置換関係をたどる必要があります。
- 現在の3区分は現行 API の公開内容に基づきます。将来 `user_editable` の指定が変われば、表示区分数も変わり得ます。
- E2E が現在の3名称を固定しているため、設定公開範囲を意図的に変更する場合は設計判断とテスト保証を同時に見直す必要があります。

## 再検討条件

- `record` / `RecordSettings` の一部または全部をユーザー編集向けに公開するとユーザーが判断した場合。
- API の `user_editable` 契約または区分生成方法を変更する場合。
- 現行の3区分のいずれかが API から非公開になった場合、または新たな編集可能区分が追加された場合。
- 候補 ID と実際の表示区分の区別が保守上分かりにくく、別の明示的な公開スキーマが必要になった場合。

## 調査した根拠

### リポジトリ内の一次情報

- `frontend/src/main/components/settings/grouping.ts`: 録画タブの候補 ID は `capture_device`、`obs`、`record`、`speech_transcriber` です。一方、存在しない区分と、`filterEditableFields` 後にフィールドが残らない区分は表示対象から除外します。
- `backend/src/splat_replay/infrastructure/adapters/storage/settings_repository.py`: モデルフィールドの `user_editable` は、指定がなければ `false` になります。
- `backend/src/splat_replay/domain/config/record.py`: `RecordSettings` の `capture_device`、`width`、`height` には `user_editable=True` がありません。
- `frontend/tests/e2e/responsive-layout.spec.ts`: 録画タブに「キャプチャデバイス」「OBS 接続」「文字起こし」の3グループが存在することを確認します。
- [旧 ADR `20260810-174636`](./20260810-174636-設定ダイアログの視認性を構造と狭幅リフローで改善する.md): 4区分の誤った前提と、維持するその他の視認性判断。
- [設計判断の実行契約](./README.md): 採用済み ADR は直接変更せず、判断変更は新しい ADR で全体または節単位の置換・追補関係を記録します。

### 実行・観測結果

- 親トランスクリプトに、実画面 DOM と `/api/settings` の表示結果が3グループであるとの照合結果が記録されています。
- 親トランスクリプトに、3区分を確認する対象 E2E が 1/1 通過した結果が記録されています。
- 記録時に上記コードとテストの現在内容を読み取りで再確認しました。テストの再実行は行っていません。

外部仕様や学術的知見は、今回の内部 ADR 運用と設定公開境界の訂正に直接関係しないため、追加調査していません。
