# macOS 通知・処理後スリープ・LAN 設定案内の方式を定める

- ID: 20260928-201438
- 状態: accepted
- 日時: 2026-09-28T20:14:38+09:00
- 判断者: ユーザー

## 目的・問題

macOS 版を正常に使えるようにする取り組みで、通知、処理後のスリープ、LAN 接続に関する OS との境界を決める。ユーザーは、利用者への影響が大きい方式選択を相談するよう依頼し、この3項目について選択した。

## 前提・制約

- 既存の macOS 対応目標は Apple Silicon 向けの機能同等である。USB 機器自動復旧は既存判断により対象外であり、本 ADR はその判断を変更しない。
- 通知方式の提案は PyObjC を追加して macOS 標準通知と権限確認を使うものだった。今回の RECORD 指示はこれを PyObjC/UserNotifications 経路として扱う。ユーザーの回答は通知名義を「Splat Replay」と明示した。
- スリープ方式の提案は `pmset sleepnow` で、失敗を画面表示するものだった。ユーザーは「windowsと同じく通知しない」と訂正した。
- LAN 方式の提案は macOS のファイアウォール設定を案内し、アプリが自動変更しないものだった。ユーザーはシステム設定を案内する方を選択した。
- 親エージェントは、実装の成功条件として OS ごとの経路、失敗の記録、Windows の動作維持を挙げた。これは会話上の実装条件であり、ユーザーが個別に述べた選択とは区別する。
- macOS の実通知、実スリープ、別端末からの LAN 接続は、提案時点で未確認と報告されていた。API・パッケージング・設定画面の具体的な実機動作は本 ADR でも確認していない。

## 判断

1. macOS の通知は PyObjC から macOS UserNotifications を使い、利用者が見る通知名義を「Splat Replay」とする。通知権限を確認する提案も採用対象とする。具体的な API 型、アプリ識別子、権限の再要求方法は未確認であり、本 ADR では定めない。
2. 処理後のスリープには提案された `pmset sleepnow` を使う。スリープ失敗をアプリ画面の通知として表示しない。失敗を記録することは、親エージェントが提示した実装成功条件として扱う。
3. LAN 接続のための macOS ファイアウォール設定はシステム設定での利用者操作として案内する。アプリからファイアウォール設定を自動変更しない。
4. これらは macOS 経路の選択であり、Windows の挙動を変更しない。

## 検討した選択肢と棄却理由

| 選択肢 | 判断 |
| --- | --- |
| macOS 標準通知を使い、Splat Replay 名義で表示する | 採用。ユーザーがこの名義を指定し、提案された通知方式を選択した。 |
| `pmset sleepnow` の失敗を画面に表示する | 不採用。これは当初の提案であり、ユーザーが「windowsと同じく通知しない」と訂正した。 |
| システム設定の案内から利用者がファイアウォールを設定する | 採用。ユーザーがシステム設定の案内を選択した。 |
| アプリがファイアウォール設定を自動変更する | 不採用。提示された案内方式は自動変更を行わないもので、ユーザーはそれを選択した。自動変更を希望した事実はない。 |

別の通知 API・スリープ手段・ファイアウォール設定方法は会話で比較されていないため、候補や棄却理由を追加しない。

## 適用範囲

Apple Silicon 向け macOS 対応における、アプリ通知の表示名と通知権限確認、処理後のスリープ実行、LAN 接続に必要なファイアウォール設定の案内。

## 適用しない範囲

- Windows の通知・スリープ・ファイアウォール挙動。
- 処理後スリープを開始する条件やタイミング。既存設定の意味は変更しない。
- macOS のファイアウォールを有効化するか、個々のポートやサービスをどのように許可するかという OS 側の設定詳細。
- Intel Mac、Linux、USB 機器自動復旧。
- 通知失敗時の追加画面表示、通知を再試行する回数、ユーザー向けの設定画面文言。

## 期待する効果

- macOS でもアプリ名が分かる通知を利用できる。
- 処理後のスリープ失敗で、ユーザーが望まないアプリ画面通知を出さない。
- LAN 利用に必要なファイアウォール設定を利用者が確認して行える。
- OS 設定をアプリが自動変更しない境界を明確にする。

## 受け入れる欠点・リスク

- PyObjC の配布・署名・実行環境との適合と、通知権限の実際の表示動作は未確認である。通知が出ない場合のユーザー向け追加表示も本判断では決めていない。
- スリープ失敗を画面通知しないため、失敗はアプリの記録から確認する必要がある。記録先や利用者向け確認手段は未確認である。
- ファイアウォール設定は利用者の操作に委ねる。設定方法と表示名は macOS の版や構成により異なる可能性があるが、差異は本記録では調査していない。
- 実通知、実スリープ、別端末からの LAN 接続を確認した判断ではない。

## 再検討条件

- PyObjC をアプリ配布物で利用できない、または通知権限を含む標準通知経路が成立しないことが確認された場合。
- `pmset sleepnow` が対象環境で機能しない、または失敗の記録だけでは利用者が必要な対応を取れない事例が確認された場合。
- macOS のファイアウォール設定案内だけでは LAN 接続を成立させられない事例が確認された場合、またはユーザーがアプリによる自動設定を明示的に求めた場合。
- macOS 対応対象や通知名義を変更する場合。

## ユーザー発言の原文

### macOS 対応の目的と確認範囲（ordinal 8、関連部分）

> このアプリがmacでも正常動作することを目標として取り組んでください。
> ユーザー影響や影響が大きい判断が必要な時は私に聞いてください。

### 選択対象となった親エージェントの提案（ordinal 9790）

> 次の3方針をまとめて承認するか、変更したい項目を指定してください。
>
> 1. 通知：PyObjC を追加し、macOS 標準の通知と権限確認を使う。
> 2. スリープ：`pmset sleepnow` を使い、失敗を画面に表示する。実スリープ試験は別途確認する。
> 3. LAN：macOS のファイアウォール設定を案内し、アプリから設定を自動変更しない。

### ユーザーの確定回答（ordinal 9797、原文どおり）

> Splat Replay 名義の通知（推奨）
> pmset （windowsと同じく通知しない）
> システム設定を案内（推奨）

### 回答後の親エージェントによる正規化（ordinal 9802、ユーザー判断と区別）

> M8 の方針を確定します。通知は「Splat Replay」名義、スリープは `pmset` で Windows と同じく画面通知なし、LAN はシステム設定の案内とします。成功条件は、それぞれ macOS の経路が動き、失敗が記録され、Windows の動作を損なわないことです。OS 操作は infrastructure と配布設定、画面案内は frontend に置き、判断を記録役へ委譲してから実装を進めます。

この後続文は親エージェントによる要約・実装条件であり、ユーザーの逐語的発言とは扱わない。
