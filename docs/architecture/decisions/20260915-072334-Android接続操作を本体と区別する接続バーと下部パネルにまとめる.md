# Android接続操作を本体と区別する接続バーと下部パネルにまとめる

- ID: 20260915-072334
- 状態: accepted
- 日時: 2026-09-15T07:23:34+09:00
- 判断者: ユーザー

## 目的・問題

Android ラッパーの接続操作をモダン化し、本体 SplatReplay の画面設計が崩れているように見える混同を避ける。Android 側の操作であることを識別できるまま、常時表示する操作を整理する。

## 前提・制約

- ユーザーは上部ボタンの維持を制約とせず、スライド表示など他の方式も比較するよう依頼した。
- 既存の自動再接続があることは親のコード調査報告による。手動再接続・接続先変更の利用頻度は未確認である。
- 本体内の「未接続」と Android から PC への接続状態を区別する。
- 本 ADR は UI 方針の承認を記録し、実装・実機確認の完了を示さない。

## 判断

1. 通常は上部に控えめな接続バーを常時表示する。表示例は「PCへの接続：接続済み                     ⌄」とし、状態の対象を明記する。
2. 接続バーをタップすると、下から「このAndroid端末の接続」パネルを開く。接続先の表示、接続先の変更、手動再接続をそこへまとめる。
3. 手動再接続は通常パネル内に置き、接続失敗時にはすぐ押せる位置へ表示する。
4. Android 側は落ち着いたチャコール系、通常の文字、シンプルなアイコンで統一する。本体のネオン表現を流用せず、細い境界線で役割を分ける。
5. スワイプだけに入口を隠す構成は採用しない。将来スライド操作を加える場合にもタップできる入口を残す。今回、追加のスワイプ操作自体を採用したわけではない。

## 検討した選択肢と棄却理由

| 選択肢 | 採否・理由 |
| --- | --- |
| 小さく状態と入口を示し、低頻度操作を必要時に開く | ADVISE の理想的な構成。具体的な採用形は接続バーと下部パネルである。操作頻度の実測はない。 |
| 中立色の接続バーと下から開くパネル | 採用。操作場所・状態・責務を伝え、本体コンテンツを常設操作で覆わない。 |
| 同じ接続バーから既存ダイアログを開く | ADVISE が挙げた最小案。最終提案と承認は下から開くパネルを選択した。この案を見送る個別の理由は明示されていない。 |
| 端からスワイプして表示 | 不採用。表示面積は増える一方、入口に気づきにくく、Android の戻る操作との競合も懸念される。競合の実機確認は未実施。 |
| 浮かぶ小さなボタン | 不採用。常設領域を小さくできる一方、本体側のボタンと誤認されたり、コンテンツを隠したりする懸念がある。 |
| 本体のネオン表現へ同化させる | 不採用。ユーザーが求める役割の識別を維持するため、中立色と境界線を使う。 |

## 適用範囲

Android ラッパーに属する接続状態、接続先表示・変更、手動再接続の視覚表現と操作入口。

## 適用しない範囲

SplatReplay 本体 Web 画面のデザイン変更、認証・通信方式・再接続間隔の変更、Windows 常駐や OBS の制御、Android アイコン、配布方式。具体的な寸法・アニメーション・実装ライブラリの採用も本承認では確定しない。

## 期待する効果

Android が担う接続管理と本体の操作を見分けやすくし、通常画面の操作量を減らしながら接続状態と入口を発見できるようにする。

## 受け入れる欠点・リスク

- 接続バーが常時画面の高さを使う。
- 接続先変更や通常時の手動再接続はパネルを開く一段階が増える。
- 配色・境界・文言による識別性、操作の分かりやすさ、実機での見た目は未確認である。
- 外部公式資料・学術資料は ADVISE 時にネットワーク制限で確認できておらず、外部標準への適合が証明された判断とは扱わない。

## 再検討条件

会話で明示された再検討条件はない。操作頻度・実機での識別性・表示面積の許容性は未確認事項として残す。スライド操作を追加する場合もタップ入口を残すという承認範囲を維持する。

## ユーザー発言の原文

依頼本文（1319 行、2026-09-15T07:07:26+09:00）:

> Androidアプリ側のボタンがダサいので、モダン化してください。
> ただし、splat replayアプリと同化すると役割の違いがあるのにsplat replayとしての画面設計が崩れているように認識されそうです。そのため、Androidアプリ側のボタンであることは区別出来るままの方がいいと思っています。あなたの意見を聞かせてください。
> なお、画面上部のボタンに固執せず、スライドさせてボタンを表示させる等、他の選択肢も検討してください。

受諾対象となったメインエージェントの提案全文（1396 行、2026-09-15T07:10:01+09:00）:

> **Android側の操作だと分かる区別は残すべき**だと思います。今の違和感は、区別そのものより、白い帯と立体的な標準ボタンが本体の雰囲気から浮いている点です。
>
> おすすめは、**控えめな接続バー＋必要なときだけ開くボトムシート**です。
>
> 通常は上部に、次の1行だけ表示します。
>
> `PCへの接続：接続済み                     ⌄`
>
> バーをタップすると、下から「このAndroid端末の接続」パネルを開き、接続先・接続先の変更・再接続を表示します。
>
> - Android側は落ち着いたチャコール系、通常の文字、シンプルなアイコンで統一します。
> - 本体のネオン表現は使わず、細い境界線で役割を分けます。
> - 自動再接続があるため、手動の「再接続」はパネル内へ移します。接続失敗時にはすぐ押せる位置に表示します。
> - 状態は「PCへの接続」と明記し、本体画面内の「未接続」と区別します。
>
> 他の方式も比較すると、次の違いがあります。
>
> | 方式 | 評価 |
> |---|---|
> | **接続バー＋下から開くパネル** | 操作場所と役割が分かりやすく、最もおすすめです |
> | 端からスワイプして表示 | 表示面積は増えますが、入口に気づきにくく、Androidの戻る操作とも競合し得ます |
> | 浮かぶ小さなボタン | 場所を取りませんが、本体のボタンに見えたり、コンテンツを隠したりします |
>
> スライド操作を採用する場合も、**スワイプだけに隠さず、タップできる入口を残す**のがよいです。まずはこの接続バー方式を推奨します。まだ実装は変更していません。
