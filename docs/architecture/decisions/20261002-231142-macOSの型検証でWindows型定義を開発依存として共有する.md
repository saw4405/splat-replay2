# macOSの型検証でWindows型定義を開発依存として共有する

- ID: 20261002-231142
- 状態: accepted
- 日時: 2026-10-02T23:11:42+09:00
- 判断者: 共同

## 目的・問題

macOS で backend の `src` と `tests` を型検証するとき、Windows 専用ライブラリの型定義不足による 15 件の診断が報告されました。実行用ライブラリを Windows 専用のまま保ち、Mac 上でも全ファイルを型検証できるようにする方法を決めます。

## 前提・制約

- ユーザーは、実行用ライブラリの Windows 条件を維持し、Windows 型定義を Mac の開発環境にも用意し、pygrabber の利用箇所だけ型宣言を置く案を確認されました。
- `backend/pyproject.toml` では実行用の Windows 依存に OS 条件が付きます。`types-pywin32` は型検証専用の開発依存として全 OS で利用します。
- `backend/pyproject.toml` の ty 設定は既存 `backend/typings` を追加パスとして参照します。
- `backend/src/splat_replay/infrastructure/adapters/capture/capture.py` が pygrabber から利用するのは `FilterGraph()` と `get_input_devices()` です。
- `backend/uv.lock` は pygrabber 0.2 を固定しています。pygrabber の stub はこの固定版のソースを根拠とし、依存更新時に再確認します。
- 型検証の成功は Windows 上での実行や機器接続を保証しません。Windows 実機の振る舞いは別の確認事項です。
- `docs/architecture/principles/README.md` に登録済みの設計指針はありません。今回の案は局所的な型定義供給の選択であり、一般指針への昇格は行いません。

## 判断

1. `pywin32`、`pygrabber`、その他の既存 Windows 実行依存に付いた Windows 条件を維持します。型検証を通すために実行用ライブラリを Mac へ追加しません。
2. `types-pywin32` は runtime 依存にせず、プラットフォーム条件のない開発依存として扱います。
3. 既存 `backend/typings/pygrabber` に限定した stub を置きます。パッケージ stub には API を宣言せず、`dshow_graph.pyi` には `FilterGraph.__init__(self) -> None` と `get_input_devices(self) -> list[str]` だけを宣言します。宣言範囲は pygrabber 0.2 の実装と実利用箇所に合わせ、未使用 API を推測で追加しません。
4. Windows 専用テストが `subprocess.CREATE_NO_WINDOW` を参照する箇所は、既存コードで使われている `getattr(subprocess, "CREATE_NO_WINDOW", 0)` の形式を用います。Windows 固有定数がない OS 上でテストモジュールの型検証・読込を妨げないためです。
5. `ty --python-platform all` への全面変更、未解決 import の包括的抑制、Windows 用ファイルの一括除外は採用しません。これらは不足している外部型定義そのものを供給せず、全ソース・テストを検査する目的を損なうか、追加範囲を広げます。
6. Mac での型検証結果と Windows での実動作保証を別々に扱います。

## 検討した選択肢と棄却理由

### Windows 実行依存を全プラットフォームへ展開する

型検証時に import を解決するためだけに `pywin32` や `pygrabber` を Mac へ導入する案です。これらは Windows API / DirectShow 用の実行依存であり、目的達成に不要な runtime 変更となるため採用しません。

### pygrabber の公開型定義を待つ、または別 OS の型検証環境だけを整える

上流が型定義を提供すれば手元の stub 保守を避けられますが、今回の作業でその供給時期を制御できません。OS ごとの CI や検証対象管理も別途維持が必要で、Mac 上で全 `src` / `tests` を型検証する目的を直ちには満たしません。

### ty の対象を全プラットフォームへ一括変更する

`python-platform = "all"` は解析時に想定する platform を指定する設定であり、不足する第三者ライブラリの型を追加しません。今回の import 解決問題を直接解かないため採用しません。

### 未解決 import を抑制する、または Windows 用ファイルをまとめて検証から外す

診断を隠すか検査範囲を狭めるため、Mac から backend 全体を型検証する目的に合いません。採用しません。

### 型依存を開発依存に移し、利用 API だけ stub を置く

実行依存の OS 条件を維持したまま型検証の入力を共有できます。pygrabber の stub はロック版と実利用箇所に限定でき、変更・保守範囲も狭いため採用します。

## 適用範囲

- macOS 上での backend `src` と `tests` 全体の ty 型検証。
- `types-pywin32` の開発依存としての共有。
- ロックされた pygrabber 0.2 と現在の利用箇所に限定した stub。
- Windows 固有 `subprocess` 定数を参照するテストでの既存 `getattr(..., 0)` パターンの利用。

## 適用しない範囲

- Windows 実行依存の OS 条件、実行時 import、製品の Windows 対応仕様を変更すること。
- Windows 実機、DirectShow、キャプチャ機器、または他の Windows API の動作を Mac の型検証で保証すること。
- pygrabber の未使用 API や、他の未型付けライブラリの API をまとめて stub 化すること。
- ty の全 OS 解析設定、import 抑制、Windows 専用ファイルの包括的除外を導入すること。
- この局所判断を、全ての第三者依存や型定義へ適用する一般指針として扱うこと。

## 期待する効果

- Windows 実行依存を Mac にインストールせずに、Mac 上で backend `src` / `tests` の型検証を実行できます。
- pygrabber の型宣言がロック版と実際に呼び出す API に限られ、将来の差分確認箇所が明確になります。
- 型検証の成功と Windows 実機の動作確認を混同せず報告できます。

## 受け入れる欠点・リスク

- pygrabber の型宣言をリポジトリ内で保守します。ロック版や利用 API を更新するとき、stub の署名が上流実装と一致するか確認する必要があります。
- 開発依存が Mac に Windows API の型情報を提供しても、Windows 固有の分岐を Mac で実行・検証したことにはなりません。
- `getattr(subprocess, "CREATE_NO_WINDOW", 0)` は定数がない環境では 0 を渡すため、Windows 専用フラグによる挙動をその環境で検査しません。
- `ty check src tests` の成功は静的型検査の結果であり、Windows 上の実行、DirectShow、またはデバイス接続の成功を意味しません。

## 再検討条件

- pygrabber のロック版を更新し、`FilterGraph` の初期化または `get_input_devices()` の戻り値が変わった場合。
- pygrabber が利用 API の正確な型定義を公式に供給した場合。
- Windows 実行依存を macOS でも実行する製品要件が追加された場合。
- `types-pywin32` の配布形式または依存関係が Mac の開発環境で利用できなくなった場合。
- ty の解析設定変更が必要になった場合、または型検証成功を実動作保証と誤認する運用上の問題が生じた場合。

### 外部一次情報

- `types-pywin32` の公式 PyPI 配布ページ: https://pypi.org/project/types-pywin32/ 。ロックされている `311.0.0.20250915` 版の wheel は `py3-none-any` であり、プラットフォーム固有 wheel ではないことを確認しました。参照日: 2026-10-02。
- `pygrabber 0.2` の公式 PyPI リリースページ: https://pypi.org/project/pygrabber/0.2/ 。DirectShow を用いる Windows 用ライブラリと記載され、例に `FilterGraph()` と `get_input_devices()` が示されています。固定版の sdist SHA-256 は `e584b119d4c9b9a8f339eb34d1fe7fdd16214a2bf5a1876171145caebdb9e413` です。worker の検証ログに期待値と実測値の一致が記録され、親エージェントはログを読み、`get_available_filters` が `list[str]` を返す実装の確認結果をレビューしました。配布物は型根拠の確認のみで、Windows ライブラリとしてインストール・実行していません。検証用アーカイブは確認後に撤去されました。参照日: 2026-10-02。
- Astral ty 公式設定資料: https://docs.astral.sh/ty/reference/configuration/#python-platform 。`python-platform` は解析対象のプラットフォーム指定であり、`all` はコードが任意のプラットフォームで実行可能と仮定する設定であることを確認しました。参照日: 2026-10-02。
