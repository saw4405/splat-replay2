# macOS プレビュー取得で1920×1080・60 FPSを希望する

- ID: 20261001-081935
- 状態: accepted
- 日時: 2026-10-01T08:19:35+09:00
- 判断者: ユーザー

## 目的・問題

macOS のプレビューが不鮮明に見える問題を解消するため、プレビュー映像の取得時に解像度とフレームレートの希望値を指定します。親会話の調査報告では、現状の取得映像は 640×360・30 FPS であり、解像度を指定すると同じ仮想カメラから 1920×1080 を取得できるとされました。低解像度の映像を表示枠へ拡大することが、ぼやけの原因と報告されています。

ユーザーは当初 1920×1080・30 FPS を希望し、負荷がほとんど変わらない場合は60 FPSを指定しました。その後、1080pを優先して60 FPSでよいと明示しました。判断のきっかけは macOS の画質問題ですが、取得指定は共通フロントエンド部品 `VideoPreview.svelte` に追加され、OS別分岐はありません。本 ADR はその共通部品へ1920×1080・60 FPSを希望値として設定する判断を記録します。

## 前提・制約

- `docs/architecture/decisions/20260930-221359-macOSのカメラ許可要求を解消してもプレビューの滑らかさを維持する.md` は、約1～2 FPSの既存JPEG APIへ切り替えず、滑らかさを維持する方針を定めています。30 FPSと60 FPSの優先順位は定めていません。
- 既存の取得指定である `deviceId: { exact: ... }` と `aspectRatio: { ideal: ... }` は維持します。解像度とフレームレートには `width: { ideal: 1920 }`、`height: { ideal: 1080 }`、`frameRate: { ideal: 60 }` を追加します。
- `frontend/src/main/components/recording/VideoPreview.svelte` は共通フロントエンド部品で、通常の機器指定と汎用 fallback の双方が同じ映像希望値を使います。macOS 固有の分岐はありません。したがって希望値の追加はこの部品を使う環境に適用されます。ユーザーからWindowsでは以前鮮明だったとの報告がありますが、Windows等の実取得形式と負荷は未確認です。
- 親会話の一試行では、1920×1080と30 FPSの上限を同時に指定すると `OverconstrainedError: Invalid constraint` になりました。この結果はその制約の組み合わせが当該試行で取得できなかったことを示し、すべての環境で1080p30が取得できないことを示しません。
- 後続の同環境での試行では、`ideal: 30` で1920×1080・30 FPS、`ideal: 60` で1920×1080・60 FPSを取得しました。よって1080p30も技術上の候補として残りますが、ユーザーの最終指示は60 FPSです。
- 30 FPSと60 FPSの負荷差は、短時間の一組の測定でのみ観測されています。他の機器・環境・録画や解析との同時実行時に同じ負荷差になるかは未確認です。

## 判断

1. 共通の `VideoPreview.svelte` におけるプレビュー取得で、幅1920、高さ1080、フレームレート60を希望値として指定します。macOS の実取得品質改善が判断の目的ですが、希望値の指定自体はこの部品を使う環境に共通です。
2. 新たな3項目は `ideal` とし、`max` や `exact` による上限・必須条件にはしません。映像取得元が希望値を満たせない場合は、ネイティブの取得処理による選択に委ねます。
3. 既存の `deviceId: exact` と `aspectRatio: ideal` は維持します。
4. 今回の一組の測定では60 FPS時のCPU増加が小さく観測されましたが、全環境で負荷差が小さいとは保証しません。60 FPSを選ぶ根拠は、まず1080pを優先し60 FPSを許容するというユーザーの最終指示です。

## 検討した選択肢と棄却理由

### 現状の640×360・30 FPSを維持する

変更は不要ですが、ユーザーが希望した1920×1080を取得せず、不鮮明さの原因と報告された低解像度を残すため採用しません。

### 1920×1080・30 FPSを希望値とする

当初のユーザー希望に合致します。ユーザーは、1080pを優先して60 FPSを選ぶと明示しました。その後の試行では `ideal: 30` で1080p30を取得できることも確認されました。この後続結果は最終選択の後に得られたため、ユーザーがその結果を前提に選んだとは扱いません。今回30 FPSを希望値にしない理由は最終選択に従うためであり、1080p30が不可能だからではありません。後続の短時間測定では60 FPS時のCPU増加が小さく観測されましたが、他環境の負荷差は未確認です。

### 1920×1080・30 FPSを上限として固定する

一試行で取得に失敗しました。機器の選択肢を狭める上限指定は採用せず、希望値を渡す方式にします。この一試行だけから、上限指定がすべての環境で失敗すると一般化しません。

### 60 FPS入力を後段で30 FPSへ間引く

ADVISE の候補として検討されました。入力側の60 FPS処理は残り、間引き処理も加わるため、負荷を下げる保証がありません。ユーザーが60 FPSを許容しているため、追加処理を設けず取得時の希望値で選択します。

### 既存JPEG APIへ切り替える

約1～2 FPSへの低下を避けるという既存 ADR `20260930-221359` のユーザー判断に沿わないため、今回も採用しません。

## 適用範囲

- macOS 配布アプリの WebView が仮想カメラから取得するプレビュー映像。
- 共通フロントエンド部品 `VideoPreview.svelte` における取得時の解像度とフレームレートの希望値。この部品を使う環境には同じ希望値が適用されます。
- 1080p取得を目的とする macOS の事例。Windows等の実取得品質は本 ADR で確認していません。

## 適用しない範囲

- OBSの録画出力や録画ファイルの解像度・フレームレート。
- Windows等における実取得形式・CPU負荷の検証と保証。ユーザーからWindowsでは以前鮮明だったとの報告がありますが、その環境で選ばれた実解像度や負荷は未確認です。共通部品の希望値は適用されます。
- すべてのカメラで1920×1080・60 FPSが必ず得られるという保証。
- CPU負荷の一般的な許容値、最低フレームレート、遅延の数値基準。

## 期待する効果

- 取得元が対応する環境では、現在報告されている640×360の拡大表示を避け、1920×1080の鮮明なプレビューを得られます。
- 60 FPSが得られる環境では、ユーザーが選んだ滑らかさを維持できます。
- macOS以外で同じ共通部品が使われる場合にも1080p・60 FPSを希望値として渡しますが、その環境で得られる形式や品質は未確認です。
- 希望値を満たせない環境ではネイティブ取得処理に選択を任せるため、希望値の強制による取得失敗を避けやすくなります。ただし、実際の取得結果は環境ごとに確認が必要です。

## 受け入れる欠点・リスク

- `ideal` は希望値であり、対応する取得元がない場合に1920×1080・60 FPSが得られるとは限りません。
- 一組の短い測定では、30 FPS時のCPU使用率は WebKit 12.63%、OBS 33.83%、表示は約29.96 FPSでした。60 FPS時は WebKit 13.23%、OBS 34.25%、表示は約58.30 FPSでした。1コアを100%とする観測値で、この試行の差はWebKit約0.60ポイント、OBS約0.42ポイントです。
- 上記の値は今回の実機・短時間の観測であり、他のハードウェアや録画・解析中のCPU負荷を保証しません。親会話でも録画・解析との同時実行時の負荷は未確認とされています。
- `ideal: 30` でも1080p30を得られた後続結果はあります。今回60 FPSを選んだ理由を、30 FPSが技術的に不可能だからとは説明しません。

## 再検討条件

- 対象環境で希望した1920×1080の映像を取得できない場合。
- 実際の録画・解析と同時に使った際、60 FPSの負荷がユーザーにとって許容できない場合。
- 対応機器が異なるなど、希望値と実取得値の差が運用上の問題になった場合。

再検討時は対象環境の取得設定・実測フレームレート・CPU負荷を確認してから判断します。現時点では負荷の一般的な許容閾値を定めません。

## ユーザー発言の原文

### 不鮮明なプレビューの報告（ordinal 19586、該当箇所）

> 画角は直っていました。ただ、プレビューには仮想カメラの出力を表示しているだけなので鮮明に表示されると思ってた(実際windowsで動かしてた時は鮮明だった)のですが、今はあまり鮮明ではありませんでした。なぜですか？

### 条件付きの希望（ordinal 19812、該当箇所）

> プレビューは、1920×1080・30 FPSでいいです。負荷がほとんど変わらないなら60 FPSにしてください。

この発言と同じメッセージにあった「Xマッチ選択画面」のXP認識依頼は別の判断パッケージのため、本 ADR には含めていません。

### 最終選択の直前にあった説明（ordinal 19919）

> 1080pで60 FPSの表示は確認できました。一方、今のOBS仮想カメラは1080p・30 FPSを上限として指定すると取得に失敗します。30 FPSを希望する指定で取得できる解像度を確認し、無理なく使える設定を選びます。

### 最終選択（ordinal 19930）

> 1080pがいいので、60FPSでいいです
