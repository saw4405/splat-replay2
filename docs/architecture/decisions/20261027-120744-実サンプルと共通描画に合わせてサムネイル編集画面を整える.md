# 実サンプルと共通描画に合わせてサムネイル編集画面を整える

- ID: 20261027-120744
- 状態: accepted
- 日時: 2026-10-27T12:07:44+09:00
- 判断者: メインエージェント

## 目的・問題

サムネイル編集画面のサンプル表示と操作領域を、実際のサムネイルの見た目・位置に一致させ、利用者が背景やレイヤーを画像編集ソフトに近い感覚で扱えるようにする。

ユーザーは、サンプルに実際のリザルト画面と高キルレの切り抜きを使うこと、勝敗を `{WIN} - {LOSE}` と表示し正しい位置に置くこと、背景画像の切り替え場所を見つけやすくすること、常時表示される「サンプルで編集中」の必要性を見直すことを求めた。前回提示された画面例はテスト中に値と位置を変更した画像であり、初期状態の証拠として扱えないことも明らかになった。

## 前提・制約

- 先行 ADR [`20261027-111805`](./20261027-111805-サムネイルデザインを共通設定で編集し生成開始時に固定する.md) の、設定ファイル化、サンプルを使う編集、実生成画像での確認、親設定保存、生成開始時点での固定を維持する。
- サンプルには実際のリザルト画面と高キルレの切り抜きを使う。ただし、編集のたびに利用者の実録画を選択する UI にはせず、アプリに同梱する固定サンプルとして扱う。
- デザイン編集と表示条件の確認は区別する。サンプル条件の切り替えは編集面に常時表示せず、表示確認の流れで扱う。
- ユーザーが保存済みのカスタムデザイン設定は、この画面整理やサンプルの更新によってリセットしない。
- 初期状態を示すスクリーンショットと、操作後の編集テスト画像を区別する。テスト中に変更した値・位置の画像を初期状態の証拠として提示しない。

## 判断

1. 同梱する固定サンプルに実際のリザルト画面と高キルレの切り抜きを含める。ユーザーの実録画をその場で選択する方式にはしない。
2. 初期の勝敗テンプレートは `{WIN} - {LOSE}` とし、初期配置も設定値だけで推測せず、実際の生成画像と描画要素の境界を使って正しい表示位置に合わせる。
3. 編集画面は、上部に常設の背景切り替えとツール、中央にキャンバス、右側にレイヤー一覧と選択要素の属性を置く構成にする。前面のレイヤーを一覧の上側へ表示し、選択中の要素の設定は右側で編集する。一般的なペイント・画像編集ソフトの操作配置に寄せるが、同等の機能範囲までは要求しない。
4. 「サンプル Xマッチ・2ステージ／サンプルで編集中」のような常時表示の状態文言は編集面から取り除く。どのサンプル条件を使うかの切り替えは、生成結果の表示確認フローへ移す。
5. 描画処理は編集プレビューと実サムネイル生成で共通にする。描画要素ごとの実際の出力範囲を共通描画処理から返し、編集時の選択・ドラッグ用の矩形をその範囲に一致させる。見た目の位置と操作対象の位置がずれないようにする。
6. 初期状態のスクリーンショットと、値・位置を変更した編集テストのスクリーンショットを別の証拠として扱う。どちらか一方をもう一方の状態の証拠に流用しない。
7. 保存済みのカスタムデザイン設定は保持する。固定サンプルの差し替え、表示確認条件の変更、初期状態の確認によって保存済みデザインを初期値へ戻さない。

## 検討した選択肢と棄却理由

- 実サンプルにアプリ内の実録画を選ばせる案は採用しない。以前のプレビュー方針と同様、固定サンプルで編集対象を示し、条件の違いは表示確認フローで見る。
- 背景切り替えをキャンバス下の「ベース画像」に置いたままにする案は採用しない。ユーザーが場所を尋ね、メインエージェントも現在の配置を見つけにくいと確認したため、常に見える上部へ移す。
- 「サンプルで編集中」を編集面に常時表示する案は採用しない。ユーザーが必要性を尋ね、サンプルの状態を説明する表示は表示確認側へ移す判断とした。
- 描画とは別の近似プレビュー形状を操作矩形に使う案は採用しない。共通描画が返す出力範囲を選択・ドラッグにも使い、実際に見える要素と操作対象を合わせる。
- 編集中に撮ったスクリーンショットを初期状態の証拠として使う案は採用しない。前回の画面例はテスト中に勝敗を `4 / 3` に変更し、要素を移動した後の画像だったとメインエージェントが訂正したため、初期状態と編集済み状態を分ける。
- 初期サンプルを更新する際に保存済みカスタム設定も初期化する案は採用しない。サンプルの内容と利用者の保存済み設定は異なる状態として保持する。

## 適用範囲

- サムネイルデザイン編集画面のレイアウト、背景切り替え、レイヤー一覧、属性編集。
- 編集プレビューと実生成で使う描画結果・要素境界の共有。
- 固定サンプル素材と、編集画面・表示確認フローにおけるサンプル条件の表示。
- 初期状態と編集後の画面証拠の区別、および保存済みカスタム設定の保持。

## 適用しない範囲

- 先行 ADR が定めた設定ファイル形式、親設定での保存・取消、生成開始時の設定固定の変更。
- 利用者の実録画を選択するサンプル素材ピッカー。
- ペイント・画像編集ソフトの全機能の実装。
- 保存済みカスタムデザインの自動初期化またはリセット。

## 期待する効果

- 実際の結果画面・切り抜きを見ながら、初期デザインとサンプル状態を理解できる。
- 背景切り替え、レイヤー順、選択中要素の設定を一般的な編集画面の位置関係から見つけられる。
- 表示された要素の範囲と、クリック・ドラッグ対象が一致し、位置ずれを調整しやすくなる。
- 初期状態の再現性と、編集操作の確認結果を混同せずにレビューできる。
- サンプルの変更で保存済みのカスタムデザインを失わない。

## 受け入れる欠点・リスク

- 同梱サンプルは固定されるため、すべての実データの組み合わせを編集画面で確認できるとは限らない。条件違いの表示確認を別に使う必要がある。
- ペイントソフトに似た配置は操作の手掛かりになるが、機能の範囲や細部の挙動は同じではない。
- 描画境界と操作矩形を同じ値にするには、文字・画像・切り抜きなど各要素の実際の出力範囲を正しく扱う必要がある。
- 初期状態と編集済み状態を取り違えると、既定テンプレートや位置の不具合を見落とす可能性がある。
- 既存のカスタム設定を保持するため、初期状態の確認は保存済み状態を変更せずに行える必要がある。

## 再検討条件

- 固定サンプルでは必要な素材・条件を表現できず、実録画の選択が必要と確認された場合。
- 上部背景切り替え、中央キャンバス、右レイヤー・属性という配置で背景・要素編集を見つけにくいと確認された場合。
- 描画処理の出力範囲とクリック・ドラッグ対象の不一致が残る場合。
- 条件違いの表示確認だけでは実際の編集状態を確認できないと分かった場合。
- サンプル更新でカスタム設定が変更・消失した場合。
