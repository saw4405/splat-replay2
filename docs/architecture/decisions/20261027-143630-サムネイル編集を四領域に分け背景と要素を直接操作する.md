# サムネイル編集を四領域に分け背景と要素を直接操作する

- ID: 20261027-143630
- 状態: accepted
- 日時: 2026-10-27T14:36:30+09:00
- 判断者: メインエージェント

## 目的・問題

サムネイル編集画面で、プレビュー、背景、要素の管理、選択要素の編集をそれぞれ独立した操作領域として明確にする。背景の移動・拡大、文字入力、選択中の要素の視認を迷わず行えるよう、一般的なペイント・画像編集ソフトの操作モデルへ寄せる。

ユーザーのブラウザコメントでは、背景画像の移動・拡大縮小と文字入力の方法が分からず、点線の選択表示が背景によって見づらいと指摘された。画面全体を再設計する要望も明示された。

## 前提・制約

- 先行 ADR [`20261027-111805`](./20261027-111805-サムネイルデザインを共通設定で編集し生成開始時に固定する.md) の設定ファイル、親設定による保存・取消、生成開始時点での設定固定を維持する。
- 先行 ADR [`20261027-120744`](./20261027-120744-実サンプルと共通描画に合わせてサムネイル編集画面を整える.md) の固定サンプル、共通描画、要素の実出力範囲を使った選択範囲、カスタム設定保持を維持する。
- 今回のレビュー画像は 1042×864 のビューポートで、背景操作、文字入力、選択枠の視認性が確認対象となった。
- 1042×864 と小さな画面での表示、および背景移動・倍率変更・文字編集・要素管理の実操作を検証対象とする。本 ADR は検証が完了したことを主張しない。
- 保存済みカスタムデザインと、親設定の保存・取消契約は変更しない。

## 判断

1. 編集画面を四領域に分ける。左上にプレビュー、左下に背景設定、右上に要素管理、右下に選択要素の編集を置く。
2. 各領域の見出しと主要操作は表示領域に固定する。要素管理の一覧と選択要素の編集内容は別々にスクロールさせる。右上の要素管理領域に追加・削除・選択・表示切り替えの操作と一覧を置き、前面のレイヤーを一覧の上側に表示する。要素追加ボタンは要素管理領域内に置く。
3. 背景設定領域に、背景ソース、素材選択、位置、背景倍率、位置リセット、倍率リセットを集約する。背景移動は明示的な「背景移動」モードで行う。モード中はキャンバス上のドラッグを背景移動に使い、要素選択・移動と競合させない。Escape でモードを解除する。
4. リザルト背景も共通描画処理を通じて移動・拡大できるようにする。初期値は x=0、y=0、倍率=1 とし、既存の出力画素を維持する。背景倍率の操作範囲 1〜4 は維持する。
5. 選択要素の編集領域では、文字内容を先頭に表示し、色・位置・寸法などの属性を編集する。新しい文字要素を追加した直後と、既存文字をダブルクリックしたときに文字入力欄へフォーカスする。要素を通常選択しただけでは入力欄へフォーカスを移さない。
6. 選択枠は白と黒の二重線で表示し、明るい背景・暗い背景のどちらでも見えるようにする。枠線は要素の座標や寸法を変えない。サイズ変更操作ができると誤解させるリサイズハンドル風の装飾は付けない。
7. 新しい四領域の構成は 1042×864 と小さな画面で表示を確認し、背景の移動・拡大縮小、Escape によるモード解除、文字の追加・編集、選択、表示切り替え、属性編集、スクロールを実操作で確認する。

## 検討した選択肢と棄却理由

- 背景を要素と同じ通常選択・ドラッグで操作する案は採用しない。背景操作と要素選択が競合するため、背景専用モードを明示し、Escape で解除する。
- 背景ソース、素材、位置、倍率を複数の編集領域へ分散する案は採用しない。背景を扱う操作を一か所にまとめて、背景に関する変更場所を予測できるようにする。
- 選択した文字要素を一度選ぶだけで入力欄へフォーカスする案は採用しない。通常選択で文字を意図せず編集状態にせず、追加時またはダブルクリックで入力を始める。
- 選択表示を単色の点線にする案は採用しない。背景色によって見づらくなる指摘に対し、白黒二重線を使い、操作対象の寸法は変えない。
- 実装されないサイズ変更機能があるように見えるリサイズハンドル風の飾りは採用しない。視認性のための枠と、実行できる操作を混同させない。
- 前 ADR の「上部に背景切り替え、中央にキャンバス、右側にレイヤーと属性」という配置は今回の四領域構成に置き換える。前 ADR が定めたサンプル・描画・設定保存などの判断は維持する。

## 適用範囲

- サムネイルデザイン編集画面の四領域レイアウトと各領域のスクロール境界。
- 背景の選択、移動、倍率変更、初期値への復帰、および背景移動モード。
- 要素一覧の追加・削除・選択・表示切り替え、選択中要素の編集と文字入力。
- 選択枠の視認性、要素寸法への非干渉、画面サイズごとの実操作確認。

## 適用しない範囲

- 設定ファイルの形式、サムネイル生成の保存・取消境界、生成開始時点の設定固定。
- 保存済みカスタムデザインの初期化。
- 画像編集ソフトのすべての機能や、実装されていないリサイズ操作の追加。
- 固定サンプル、共通描画と要素実測範囲を定める先行 ADR の判断変更。ただし、画面配置は本 ADR の四領域構成を優先する。

## 期待する効果

- 背景をどこで選び、どう動かし、どう拡大するかが背景設定領域から分かる。
- 背景移動と要素操作の入力が競合せず、明示操作で切り替えられる。
- 文字を追加・選択・編集する手順が分かり、通常選択による意図しない入力状態を避けられる。
- 選択枠を明暗どちらの背景でも識別でき、枠表示による要素サイズの変化を避けられる。
- 領域ごとの見出しと主要操作を保ちながら、一覧と編集内容を独立して閲覧できる。

## 受け入れる欠点・リスク

- 背景移動に明示モードが必要となり、モードの有効状態が見えにくいと操作を誤るおそれがある。
- 四領域を狭い画面に同時表示すると各領域が小さくなる可能性がある。小さな画面でもプレビューと主要操作が使えることを確認する必要がある。
- Escape は背景移動モード解除に使う。フォーカス中のテキスト編集など別の操作状態と競合しないことを確認する必要がある。
- 選択枠は視認性を優先する一方、リサイズハンドルを表示しないため、要素サイズ変更は属性編集領域で行う。
- 背景倍率の範囲を 1〜4 に維持するため、縮小が必要となった場合は別判断が必要である。

## 再検討条件

- 1042×864 または小さな画面で四領域の見出し・主要操作・プレビューが同時に使えない場合。
- 背景移動モードと Escape 解除が要素選択・文字入力と競合する場合。
- 白黒二重線が特定の背景で識別できない、または枠が要素の寸法・位置へ影響する場合。
- 利用者が背景倍率 1 未満、または直接リサイズ操作を必要とする場合。
- 文字追加時・ダブルクリック時の入力導線と通常選択時のフォーカス境界が利用者の操作と合わない場合。
