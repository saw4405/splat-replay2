# replay E2Eの武器認識をfixture観測アダプタで分離する

- ID: 20260828-081339
- 状態: accepted
- 日時: 2026-08-28T08:13:39+09:00
- 判断者: メインエージェント

## 目的・問題

WSL2/Linux の replay workflow E2E で、CPU、OpenMP、OS 差の影響を受ける実武器 CV を合否要因から外しながら、武器認識後の状態遷移、保存、API、UI は実経路で検証します。

完成済み `RecordingMetadata` を fixture から注入すると、検証したい application の状態遷移と後続経路を飛ばしてしまいます。一方、実 CV を workflow E2E に残すと、ハードウェア非依存の可搬性ゲートが実行環境差で不安定になります。

## 前提・制約

- `live` の `WeaponRecognitionPort` 実装とユーザー向け挙動は変更しません。
- `RuntimeProfile.REPLAY` の profile 選択とアダプタ組み立ては、既存 ADR のとおり Composition Root に置きます。
- domain/application は profile、sidecar、E2E 環境変数へ依存しません。
- backend は fixture の隣接 sidecar を推測して読みません。E2E 側で検証済みの replay input から `observations` だけを受け取ります。
- `expected` は UI・永続化に対する独立期待値であり、backend へ渡しません。

## 判断

1. `RuntimeProfile.REPLAY` では、`WeaponRecognitionPort` を infrastructure の `ReplayWeaponRecognitionAdapter` に差し替えます。`live` では既存の実 CV 実装を維持します。
2. replay adapter は fixture 由来の構造化 `observations` から、武器表示判定と 8 slot の認識結果を返します。完成済み `RecordingMetadata` は注入しません。
3. observation が不足、不正、slot 不一致の場合は fail-fast とし、live 実装、推測値、既定値へ fallback しません。
4. sidecar は `schema_version`、`scenario`、`observations`、`expected` を分離します。backend に転記する対象は `observations` だけです。
5. 実 Tesseract/OCR と実武器 CV の精度・性能は workflow E2E の必須条件から外し、logic、contract、performance、または条件付き統合テストで保証します。

## 検討した選択肢と棄却理由

### 完成済み RecordingMetadata を注入する

保存前の状態遷移、マージ、イベント、API の実経路を飛ばし、workflow の保証を失うため採用しません。

### replay の WeaponRecognitionPort を fixture 観測アダプタへ差し替える

外部 CV だけをポート境界で test double 化し、以降の application、storage、API、UI を実経路で保持できます。既存の Composition Root 分離と Clean Architecture の依存方向に適合するため採用します。

### 実 CV を残し、E2E 期待値を緩めるか skip する

CPU・OS 差による不安定性を残し、可搬性ゲートが何を保証するかも不明確になるため採用しません。

### 全ての外部認識器を同時に観測化する

理想的には各外部認識器をポート境界で replay 可能にしますが、今回の不安定観測は武器 CV であり、最小の現実案として対象を `WeaponRecognitionPort` に限定します。

## 適用範囲

- replay profile の `WeaponRecognitionPort` 登録と replay adapter。
- replay input と E2E fixture の `observations` 契約、および武器表示・8 slot の検証。
- WSL2/Linux replay workflow E2E が保証する、武器認識後の状態遷移、保存、API、UI の実経路。

## 適用しない範囲

- `live` の実武器 CV、Tesseract/OCR、NDI、OBS の精度・性能・実機統合保証。
- macOS の native 実機、配布、署名、notarization の保証。
- Linux をエンドユーザー向けの正式対応 OS にする判断。
- テスト入口や CI コマンドの選定。

## 期待する効果

- WSL2/Linux workflow E2E の合否を実 CV の CPU・OpenMP・OS 差から分離できます。
- 期待値と外部認識器の入力観測を分離し、fixture が完成結果を注入することを防げます。
- replay で observation 不備を見逃さず、誤った live fallback による偽合格を防げます。

## 受け入れる欠点・リスク

- workflow E2E 単独では実 CV の精度・性能回帰を検出しません。別保証層が必要です。
- fixture observation の schema と実ポート契約が乖離するリスクがあります。schema validation と contract テストで検出します。
- 今回は OCR を観測化しません。実 Tesseract/OCR が workflow E2E に残る場合、その外部依存は別判断で分離する必要があります。

## 再検討条件

- replay observation が実際のポート契約を表現できず、application の主要分岐を失うと確認されたとき。
- 実 CV の保証を workflow E2E に再び含めるプロダクト上の理由が生じたとき。
- OCR を含む他の外部認識器にも同じ可搬性・不安定性が確認されたとき。
- macOS の native 実機統合を開始するとき。

## ユーザー発言の原文

ユーザーは当初、次の目的と制約を示しました。

> 最終的にmacosで動作するようにしたいです。
> ただmacは今ないので、まずはlinux(wsl2)でテスト合格(e2e含む)する状態をゴールとします。
> アーキテクチャなど重要な判断(間違うと手戻りが大きい)をするときには、サブエージェント(sol)にアドバイスを求めてください。

Sol と design_steward の助言後、メインエージェントは次を確定しました。

> 助言を踏まえ、WSL2 の workflow E2E では外部の武器 CV を既存ポートで replay 観測に差し替え、録画・保存・API・UI は実経路のまま検証する方針にします。実 Tesseract/OCR の精度検証は workflow から分離し、別の保証層に置きます。これによりテスト方針との不整合を解消します。

RECORD 依頼で、`ReplayWeaponRecognitionAdapter`、`schema_version`・`scenario`・`observations`・`expected` の分離、observation の fail-fast、live fallback 禁止、backend には observations のみを転記すること、完成済み `RecordingMetadata` を注入しないことが、メインエージェントにより具体化・確定されました。これらはユーザー原文には含まれない実装境界の正規化であることを明記します。
