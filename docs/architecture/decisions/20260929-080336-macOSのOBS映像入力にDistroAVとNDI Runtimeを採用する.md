# macOS の OBS 映像入力に DistroAV と NDI Runtime を採用する

- ID: 20260929-080336
- 状態: accepted
- 日時: 2026-09-29T08:03:36+09:00
- 判断者: ユーザー

## 目的・問題

Apple Silicon 搭載 Mac でも全機能を同等に利用できるようにする方針の下で、OBS に入力された MiraBox Capture の映像をアプリの自動判定へ渡す方式を決めます。

このセッションの報告では、OBS 上では MiraBox の映像が表示されていましたが、アプリの LIVE 入力は NDI 受信経路で、OBS 側の NDI 送出が用意されていませんでした。NDI の導入済み判定だけでは映像がアプリまで届くことを確認できないため、入力方式の選択が必要でした。

## 前提・制約

- ユーザーは macOS 上でアプリが正常動作することを目標とし、利用者への影響が大きい判断は自身へ確認するよう求めています。
- ユーザーが先に確定した macOS 対応範囲は、全機能同等、Apple Silicon のみです。
- ユーザーは MiraBox Capture を接続したと報告しています。OBS の MiraBox ソースに Switch 映像が表示され、60 FPS と確認できたことは assistant の実機確認報告です。
- セッション中の調査報告では、既存の LIVE 入力は `AdaptiveCapture → NDICapture` であり、OBS の DistroAV/NDI 送出機能と NDI Runtime は確認できませんでした。既存 NDI checker は Finder の初期化を確認するだけで、NDI 送信元やアプリへの実映像受信までは確認しません。
- `docs/architecture/principles/README.md` に現在有効な設計指針は登録されていません。方式を選別するプロジェクト指針がないため、追加依存とアプリ改修・権限確認のトレードオフはユーザー判断に委ねられました。
- DistroAV と NDI Runtime の具体的な版、配布元、導入・更新方法、NDI 送出のセットアップ検査方法は未確認です。

## 判断

1. macOS の OBS 映像入力には DistroAV と NDI Runtime を導入し、OBS から NDI 送出して既存の NDI 受信経路へ映像を渡す方式を採用します。
2. この入力方式のために OBS Virtual Camera を読む別の backend adapter は追加しません。
3. この判断は入力方式の選択です。DistroAV/NDI Runtime の導入や、MiraBox 映像がアプリの NDI receiver に到達することが確認済みという意味ではありません。

## 検討した選択肢と棄却理由

### DistroAV と NDI Runtime を導入する

既存実装の NDI receiver に接続できる案として提示され、ユーザーが選択しました。OBS 側へ追加のプラグインと Runtime が必要になります。ユーザーが選択したこと以外に、採用理由の詳細は明示されていません。

### OBS Virtual Camera を判定入力に使う

追加プラグインは不要ですが、アプリ改修と権限検証が必要な案として提示されました。ユーザーはこの案を選ばず、NDI 方式を選択しました。選ばなかった理由の詳細は明示されていません。

## 適用範囲

- Apple Silicon 搭載 Mac 上の OBS から、MiraBox Capture の映像をアプリの自動判定用 LIVE NDI 入力へ渡す方式。
- DistroAV と NDI Runtime を含む OBS 側 NDI 送出の初回セットアップ確認・利用者案内を検討する際の方式上の前提。

## 適用しない範囲

- Windows 版の OBS・キャプチャ入力方式。
- OBS Virtual Camera を使う macOS 向け backend adapter の設計・実装。
- DistroAV または NDI Runtime の具体的な導入元、版、更新・削除、アプリによる自動導入の可否。
- NDI 実映像の受信、録画、編集、アップロードなど、全機能同等の受け入れ完了判定。

## 期待する効果

- 現行の NDI 受信経路を使い、OBS に入力済みの MiraBox 映像をアプリの自動判定へ渡す構成を取れます。
- OBS Virtual Camera 用の別入力 adapter を追加せずに済む可能性があります。実機での接続成立は未確認です。

## 受け入れる欠点・リスク

- OBS 側に DistroAV と NDI Runtime という外部要素が必要です。導入・更新の負担、利用可能な版、配布条件は未確認です。
- 現行 NDI checker は実映像の受信を保証しません。準備状態が成功でも映像が届かない可能性を排除できず、送出から receiver までの検査は未完了です。
- DistroAV/NDI Runtime の導入や実映像受信が成立しない場合、現在選んだ方式だけでは目的を達成できません。

## 再検討条件

- Apple Silicon の対象環境で DistroAV または NDI Runtime を導入・利用できないと確認された場合。
- OBS から NDI 送出してもアプリの receiver に MiraBox 映像が届かない場合。
- 初回セットアップで外部要素の導入・更新負担が許容できない、または現行 NDI 検査では必要な準備状態を判定できないと分かった場合。その場合は OBS Virtual Camera 案を含め、方式をユーザーに再確認します。

## 関連する設計指針

適用可能な設計指針はありません。設計指針索引には現在有効な指針がなく、本件は macOS の個別入力方式の選択であるため、新しい指針には昇格しません。
