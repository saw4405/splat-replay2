# Capture Controlの待受と一時停止をREADYとPAUSEで示し操作ボタンを枠内に収める

- ID: 20260814-230818
- 状態: accepted
- 日時: 2026-08-14T23:08:18+09:00
- 判断者: 共同

## 目的・問題

Capture Control の録画中表示は `REC` である一方、一時停止表示は日本語の「一時停止」であり、同じ計器内の状態短語として表記体系が揃っていなかった。また、バトル待受のゲームパッド単体では「録画準備完了」の意味が十分に伝わらなかった。

加えて、展開時の手動操作ボタンがツールバーの枠からはみ出して見える問題があった。表示を隠すだけではなく、操作領域とフォーカス表示を含めて Capture Control の外枠内へ収める必要がある。

## 前提・制約

- `recording` の可視短語 `REC`、`paused` のオレンジ色、`armed` のシアンのゲームパッドという既存の状態表現は維持する。
- 可視短語を英語へ揃えても、日本語で状態と操作を理解できるアクセシブルネームは維持する。
- 手動操作ボタンの 40px の操作領域は縮小しない。
- 状態アイコンは録画操作そのものではなく、手動操作を展開するトリガーである。
- Switch 電源 OFF、キャプチャーデバイス未接続、確認中では手動操作を表示しない既存判断を変更しない。
- hover、focus、tap、Escape、`role="toolbar"` に関する操作契約を変更しない。
- 色は既存のテーマ変数を使用し、色だけで状態を区別しない。

## 判断

1. `paused` の可視表示を、オレンジの Pause アイコンと「一時停止」から、オレンジの Pause アイコンと `PAUSE` へ変更する。`REC` と同じ、計器的な英語の大文字短語として統一する。
2. 可視短語を `PAUSE` にしても、日本語の意味と操作は `aria-label` などで維持する。状態は「録画を一時停止しています」、操作は「録画を一時停止」「録画を再開」のように、状態と操作を区別する。
3. `armed` の可視表示を、シアンのゲームパッド単体から、シアンのゲームパッドと `READY` へ変更する。`READY` は「録画準備完了」を示す状態短語として使用する。
4. Capture Control は、40px の状態・手動操作ボタンを維持しながら、縦の外寸を 48px とする。展開部はボタン間と右端の余白を各 4px とし、1ボタン時は44px、2ボタン時は88px相当の領域を確保する。
5. フォーカスリングはボタンの内側へ描画し、ポインター操作時だけでなくキーボード操作時も外枠内に収める。

## 検討した選択肢と棄却理由

### バトル待受に「ゲームを楽しんで」の意味を持つ英語を表示する

`ENJOY!` などの表現は親しみや楽しさを伝えられる一方、録画の準備が完了しているという現在状態を保証しない。Capture Control の第一責務である録画可否の判断を曖昧にするため採用せず、`READY` を採用した。

### バトル待受をゲームパッド単体のままにする

簡潔だが、「準備完了」の意味が抽象的であることは先行 ADR でもリスクとして認識されていた。今回、ユーザーが `READY` の追加を明示したため、先行判断の再検討条件を満たす変更として採用しない。

### 一時停止の可視短語を日本語の「一時停止」のままにする

意味は直接伝わるが、同一コントロール内の `REC` と表記体系が揃わない。可視表示は `REC / PAUSE / READY` に揃え、日本語の意味はアクセシブルネームで維持するため採用しない。

### 親の `overflow` を解除して、はみ出した操作やフォーカスリングを見せる

ボタンと外枠の寸法不整合を解消せず、丸い外枠から内容が漏れる可能性が残る。Capture Control の視覚的な境界と操作領域が一致しないため採用しない。

### 手動操作ボタンを縮小する

外枠内には収まりやすくなるが、既存の 40px の操作領域を失う。操作性を下げずに外枠と余白を整合させられるため採用しない。

### 外枠だけを広げ、外側フォーカスリングを維持する

通常時のボタンは収まっても、キーボードフォーカス時に再び境界を越える余地が残る。フォーカス状態を含めて枠内へ収めるため採用しない。

## 適用範囲

- メイン画面のゲームプレビュー左上にある Capture Control。
- `armed` と `paused` の折りたたみ時の可視状態表現。
- `armed`、`recording`、`paused` で展開する手動操作領域の外寸、間隔、右余白、フォーカス表示。
- 状態表示と手動操作の日本語アクセシブルネーム。

## 適用しない範囲

- `recording` の赤い録画点と `REC`。
- Switch 電源 OFF、キャプチャーデバイス未接続、確認中の表示と手動操作可否。
- 自動録画、Switch 電源監視、キャプチャーデバイス切断判定の状態遷移や精度。
- 手動録画 API、録画開始・一時停止・再開・停止の動作。
- 編集・アップロード進捗の表示。
- Capture Control 以外のツールバーや、アプリ全体の寸法体系。

## 期待する効果

- `REC / PAUSE / READY` という短い大文字の状態語で、同一コントロール内の表示体系が揃う。
- ゲームパッドだけでは曖昧だったバトル待受が、「録画準備完了」であると判断しやすくなる。
- 英語の可視短語を採用しても、日本語のアクセシブルネームによって状態と操作の意味を失わない。
- マウス、タッチ、キーボードのいずれでも、手動操作ボタンとフォーカス表示が Capture Control の枠内に収まる。
- 操作領域を縮小せず、表示境界と実際の操作領域が一致する。

## 受け入れる欠点・リスク

- `READY` は何の準備が完了しているかを単語だけでは限定しないため、ゲームパッドとの組み合わせとアクセシブルネームに依存する。
- 英語に不慣れな利用者には `PAUSE` と `READY` の意味が直ちに伝わらない可能性がある。可視領域の簡潔さを優先し、日本語の意味はアクセシブルネームで補う。
- 外寸を 42px から 48px へ変更するため、プレビュー左上で占める高さと展開時の横幅が増える。
- 1ボタン44px・2ボタン88px相当という寸法は、現在の40pxボタンと4px間隔を前提とする。ボタン数や操作領域を変える場合は再計算が必要になる。

## 再検討条件

- 利用確認で `READY` が録画準備完了ではなく、ゲーム起動完了や接続完了と誤解される場合。
- `PAUSE` または `READY` の可視短語だけでは状態を理解できない利用者が多いと判明した場合。
- Capture Control に3個以上の手動操作ボタンを同時表示する場合。
- ボタンの操作領域、フォーカスリング、外枠の形状、またはデザイントークンを変更する場合。
- 48px の外寸がプレビュー映像や他のオーバーレイと干渉する場合。
- `armed`、`paused`、録画不能状態の意味または優先順位を変更する場合。

## ユーザー発言の原文

今回の表示変更とレイアウト問題を指定した原文:

> 録画が「REC」なんだから、一時停止は「PAUSE」じゃない？
> ゲームアイコンのときは「READY」と表示して。それか、ゲームを楽しんで！ていう意味の英語がいいかな
> 後、手動操作のボタンがツールバーの枠からはみ出てる

候補を評価し、修正方針を示したメインエージェントの提案:

> `READY`を採用するのが適切です。`ENJOY!`は雰囲気は良いものの、自動録画の準備完了という肝心の状態が伝わりません。`REC / PAUSE / READY`で状態語を英語・大文字に統一し、同時にツールバーの実寸と展開幅を見直して、操作ボタンが枠内に収まるよう修正します。
>
> テスト変更を伴うため、`test-ops`の方針を再確認します。また、既存ADRの「ゲームアイコンのみ」を更新する判断になるため、`design_steward`へ先に整合性を確認させます。

根本原因と寸法方針を説明したメインエージェントの原文:

> 設計助言でも、`READY`は録画準備状態を正確に表し、`ENJOY!`系は状態保証にならないため不採用、`PAUSE`は`REC`と同じ計器的な短語として統一する結論です。はみ出して見える根因は、外枠42pxの内寸40pxに対してボタンも40pxで余白がゼロだったことでした。ボタンの操作領域40pxは維持し、外枠を48px・ボタン間と右余白を4pxに揃えて修正します。

実寸確認後、追補として記録することを示したメインエージェントの原文:

> 実寸E2Eは成功し、外枠48px・ボタン40px・間隔4px・2ボタンとも枠内という保証をChromiumで確認できました。一時設定は削除済みです。`READY / PAUSE`は既存ADRの再検討条件に該当する確定変更なので、プロジェクト契約に従い、既存ADRを改変せず追補ADRとして記録します。
