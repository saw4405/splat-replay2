# 動作確認用ADRは製品設計と実装を変更せず検証目的を明記する

- ID: 20260921-163308
- 状態: accepted
- 日時: 2026-09-21T16:33:08+09:00
- 判断者: 共同

## 目的・問題

ADR 記録エージェントの正常な記録経路を、内容が単純で影響範囲を限定できる ADR の作成によって確認する。

## 前提・制約

- ユーザーは ADR 記録エージェントの動作確認を目的として、簡単な ADR の記録を明示的に求めた。
- この ADR は製品設計、製品の振る舞い、実装、テストを変更しない。
- 対象は ADR 記録エージェントの検証目的を記録することだけであり、製品に適用する一般則を新設しない。
- 初回の記録は親トランスクリプトを取得できず失敗した。その後、親セッションで取得経路が修正・検証され、同じ記録要求が再実行された。修正内容自体はこの ADR の判断対象ではない。

## 判断

動作確認用 ADR は、製品設計・実装を変更せず、ADR 記録エージェントの検証目的であることを明記する。

## 検討した選択肢と棄却理由

| 選択肢 | 採否と理由 |
| --- | --- |
| 製品設計・実装を変更しない動作確認用 ADR を記録する | 採用。ユーザーが求めた記録動作を、製品への影響を持ち込まず確認できる。 |
| 製品に関する新しい設計判断を作って記録する | 不採用。動作確認という目的に不要であり、製品へ意図しない判断を追加する。 |
| ADR を記録しない | 不採用。ユーザーが明示的に記録を求めており、RECORD 契約の記録基準を満たす。 |
| 製品の一般的な設計指針へ昇格する | 不採用。一回限りの検証目的であり、複数の設計判断を選別する再利用可能な規範ではない。 |

## 適用範囲

本 ADR ファイルと、これを作成する ADR 記録エージェントの動作確認。

## 適用しない範囲

- 製品の要件、アーキテクチャ、実装、テスト、運用。
- ADR 記録エージェントや SubagentStart フックの実装方針。
- 他の ADR の採否や、今後の ADR に対する一般的な内容制約。
- `docs/architecture/principles/**` の設計指針。

## 期待する効果

親トランスクリプトの原文を根拠として、必須項目、原文、会話カバレッジを備えた ADR を所定の保存先へ作成できることを確認できる。

## 受け入れる欠点・リスク

- 製品設計上の価値は持たず、動作確認の履歴として ADR が一件増える。
- このファイルの作成だけでは、ADR 記録機構のすべての入力形式、失敗経路、将来の互換性までは保証しない。
- 親セッションで報告された回帰テスト結果は、本 RECORD が独立して再実行した事実ではない。

## 再検討条件

この ADR の検証目的を超えて製品設計・実装へ適用しようとする場合、または一般的な設計指針として扱おうとする場合は、別の設計判断として改めて検討する。

## 記録時セルフレビュー

- 保存直前に親トランスクリプトの対象メッセージを再走査し、ユーザーの目的、最小判断、初回失敗、訂正、再実行の受諾を照合した。
- 正規化した判断は「動作確認用 ADR は製品設計・実装を変更せず、検証目的を明記する」であり、原文の意図を拡張していない。
- 「続けて」には直前の確認対象を併記し、フック修正の詳細をユーザーが個別に設計したとは扱っていない。
- 検討案と棄却理由、一般原則へ昇格しない制約、保証しない範囲を記録した。
- 事実、親セッションからの報告、未保証事項を区別し、未確認事項を推測で補っていない。
- 記録する原文に機密情報、認証情報、個人の機微情報は含まれていない。
- 書き込みは本 ADR のみであり、コード、テスト、AGENTS.md、internal_design、設計指針、Git のステージ・コミットには触れていない。
