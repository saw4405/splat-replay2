# SplatReplay自身を常駐させAndroidから利用し更新時だけ完全終了する

- ID: 20260913-224011
- 状態: accepted
- 日時: 2026-09-13T22:40:11+09:00
- 判断者: ユーザー

## 目的・問題

Android アプリを開くことで、自宅 Wi-Fi 内の PC のデスクトップ版 SplatReplay をスマホ上で利用できるようにする。別の起動用常駐アプリとの二重管理を避けながら、SplatReplay 本体の更新と、スマホを開かない場合の自動録画を成立させる。

## 前提・制約

- 対象はデスクトップへ配置した SplatReplay と Android、自宅 Wi-Fi 内での利用である。
- PC の電源が入り、Windows へログインし、覚醒している利用を対象とする。スリープ復帰は対象外という提案上の前提であり、自動スリープの既存設定を変更する判断はしていない。
- スマホの画面表示と、Switch の監視・自動録画開始条件を分ける。
- 記録時点では実装・配布版の動作確認は未完了である。待機負荷の実測値も未確認である。

## 判断

1. 起動要求専用の別常駐アプリを設ける構成ではなく、SplatReplay 自身を通知領域へ常駐させる。Windows ログイン時の常駐を提案の方向とするが、登録方法や設定 UI の詳細は本判断で確定しない。
2. 通知領域には「画面を開く」「完全終了」を用意する。ウィンドウの × は画面を非表示にして常駐を続ける動作とし、明示的な完全終了と分離する。
3. Android アプリから常駐中の SplatReplay の画面へ接続して表示する。更新中に接続が切れた場合は再接続し、更新後に画面を再読み込みする。Android の具体的な実装方式、認証・接続先設定の詳細は未確定である。
4. スマホを開かなくても、Switch のプレイ開始を検知して自動録画する動作を維持する。「接続に必要な機能だけを待機させ、Android 利用開始時に監視を始める」途中案は採用しない。
5. 更新時は録画・編集・アップロードの処理完了を待ち、SplatReplay を正常に完全終了してから本体を更新する。設定や録画データを保持し、失敗時に戻せるよう旧版も保持する。更新後は再起動してスマホから接続できる常駐状態へ戻す。終了から再起動は更新時だけ動くスクリプトが担う。
6. 更新予約後にも Switch を使い続ける場合の、録画継続優先と新規録画抑止のどちらを選ぶかは未確定である。処理完了待ちの採用を、新規録画抑止への承認と解釈しない。

## 検討した選択肢と棄却理由

| 選択肢 | 採否と理由 |
| --- | --- |
| 別の小さな常駐アプリが SplatReplay を起動する | 今回は不採用。従来の終了動作を維持しやすく待機負荷を小さくできる一方、起動受付・認証・二重起動防止と別アプリの管理が増える。 |
| SplatReplay 自身が常駐する | 採用。管理を集約し、Android から起動待ちを挟まず画面へ接続できる。× と完全終了の分離および更新手順の変更を伴う。 |
| 待機中はスマホ接続機能だけを動かし、利用開始時に録画処理を動かす | 途中提案を不採用。スマホ不在での Switch 検知・自動録画という後続の明示回答を満たさない。親の調査報告では現行の Switch 検知に OBS 経由の映像が必要であり、OBS 停止による低負荷待機を採用済みと扱わない。 |
| 更新のための別常駐アプリを用意する | 不採用。更新時だけ動くスクリプトで終了・更新・再起動を担う。 |
| 更新予約後は録画を優先して Switch のスリープと後処理を待つ／進行中処理完了後は新規録画を抑止して更新する | 質問中。いずれも採否未確定であり、本 ADR では選択しない。 |

## 適用範囲

デスクトップ版の常駐と画面の生存期間、Android からの自宅内利用、常駐と独立した自動録画、および更新時の終了・データ保持・再起動の責務境界。

## 適用しない範囲

- 外出先接続、PC の電源投入やスリープ復帰、自動スリープ設定の変更。
- Android アプリのライブラリ、配布方法、認証方式、ポート、API、更新待ち状態機械の詳細。
- 更新予約中の録画優先順位の確定。
- 既存の OBS 起動由来・終了所有権、起動時未処理動画の自動処理条件の変更。
- 実装準備文書全体への包括的承認。

## 期待する効果

Android からの利用を SplatReplay の常駐へ集約し、PC 画面を閉じても自動録画を維持できる。更新はユーザーデータを保持して常駐へ復帰できる。

## 受け入れる欠点・リスク

- 常駐のため待機資源を消費する。OBS を含む負荷の許容性・実測値は未確認である。
- × の意味が完全終了から非表示へ変わるため、完全終了の明示導線が必要になる。
- 更新中には Android の接続が一時的に切れる。
- 処理完了待ちにより更新開始が遅れ得る。遊び続けた場合の待ち方は未確定である。
- 正常終了、旧版復帰、データ保持の具体的な失敗処理と検証は実装時に必要であり、本記録は成功の証明ではない。

## 再検討条件

更新予約中の録画優先順位をユーザーが確定した場合は後続判断へ記録する。待機負荷が許容できない、PC 覚醒以外の利用が必要、Android 表示要件が Web 画面から PC 全体の遠隔操作へ変わる場合も再検討する。

## ユーザー発言の原文

対象の指定と目的（9・21・48 行）:

> スマホからこのpcのアプリ起動できない？

> デスクトップに配置したSplatReplayです。
> Androidから自宅内のwifiだけでいいです。

> Androidのアプリを起動すると、SplatReplayを起動し、スマホ上でSplatReplayが表示されるようにしたい

比較と更新の問い（58・68 行）:

> 常駐アプリがSplatReplayを起動するのと、SplatReplayが常駐してるのだとどっちがいい？

> SplatReplayを更新するときはどうしよう？

受諾対象となったメインエージェントの提案全文（71 行）:

> **更新時だけSplatReplayを完全終了し、更新後に常駐へ戻す**運用でよいです。更新のためだけに、別の常駐アプリを用意する必要はありません。
>
> 更新の流れは次のようにします。
>
> 1. 録画・編集・アップロード中なら、処理の完了を待ちます。
> 2. SplatReplayを完全終了します。
> 3. アプリ本体を更新します。設定や録画データは残します。
> 4. SplatReplayを再起動し、スマホから接続できる状態へ戻します。
>
> 終了から再起動までは、**更新時だけ動くスクリプト**に任せられます。更新失敗時に戻せるよう、旧版も保持します。
>
> 通知領域には「画面を開く」「完全終了」を用意し、ウィンドウの×は常駐を続ける動作にします。Android側は更新中に接続が切れたら再接続し、更新後に画面を再読み込みする形がよいです。
>
> なお、これは設計案です。現在の更新手順やOBSの終了処理との整合性は、実装前に確認が必要です。

上記へのユーザー回答（78 行）:

> いいね、続けて

後続で採用しなかった途中案（メインエージェント、61 行から原文抜粋）:

> おすすめは、Windowsへのログイン時にSplatReplayを通知領域へ常駐させ、待機中はスマホからの接続に必要な機能だけを動かす形です。Androidアプリを開いたら画面を表示し、録画に必要な処理は利用開始時に動かします。

自動録画条件の質問原文（107・138 行）:

> 常駐中の自動録画は、どちらの動作にしますか？ Androidで画面を開くことと、録画の開始条件を分けて確定したいです。

質問の選択肢原文:

> スマホを開かなくても、Switchのプレイ開始を検知して自動録画する（推奨）

> Androidで利用開始したときだけ、Switchの監視・自動録画を動かす

ユーザー回答原文（138 行の answer 値）:

> スマホを開かなくても、Switchのプレイ開始を検知して自動録画する（推奨）

未回答の更新優先順位質問と選択肢（210 行）:

> 更新を予約したあともSwitchで遊び続けている場合、どちらを優先しますか？

> 録画を優先し、Switchをスリープして編集・アップロードも終わってから更新する（推奨）

> 進行中の録画・処理が終わったら更新し、その間の新しい録画は開始しない
