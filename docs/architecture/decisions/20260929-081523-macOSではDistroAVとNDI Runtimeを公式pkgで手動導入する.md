# macOS では DistroAV と NDI Runtime を公式 pkg で手動導入する

- ID: 20260929-081523
- 状態: accepted
- 日時: 2026-09-29T08:15:23+09:00
- 判断者: ユーザー

## 目的・問題

先行 ADR は、macOS の OBS 映像を DistroAV と NDI Runtime で NDI 送出し、アプリの既存 NDI 受信経路へ渡す方式を選択しました。公式配布物を使うか、利用者がどのように導入するかは未決定でした。

製品版の初回設定に載せる DistroAV と NDI Runtime の導入方法を確定します。

## 前提・制約

- 対象は先行 ADR の範囲に従い、Apple Silicon 搭載 Mac です。
- 先行 ADR「macOS の OBS 映像入力に DistroAV と NDI Runtime を採用する」は、OBS Virtual Camera 用の別 adapter を設けず、NDI 送出を既存の受信経路へつなぐ判断です。
- 質問前の assistant 報告では、現在の「NDI 導入済み」判定は同梱ライブラリで受信器を開けることを確認するだけで、DistroAV、NDI Runtime、OBS の NDI 送出、実映像の到達は確認しないとされています。この記録では、その報告を会話上の調査結果として扱います。
- 受諾対象の質問では、公式 pkg の導入後に OBS の再起動が必要で、NDI Runtime は管理者認証を求める場合があると説明されています。これらは質問中の説明であり、この ADR では外部資料による独立確認をしていません。
- 公式 pkg の具体的な入手 URL、バージョン、更新・削除手順、製品画面上の案内方法は未確認です。
- 設計指針索引には現在有効な設計指針は登録されていません。

## 判断

製品版では、macOS の利用者が DistroAV と NDI Runtime の公式 pkg を手動で導入する手順を案内します。

この判断は導入方法を定めます。具体的な pkg の URL・版・更新方法や、導入後に映像がアプリへ届くことの確認を完了した意味ではありません。

## 検討した選択肢と棄却理由

### 公式 pkg を利用者が手動導入する

採用します。ユーザーは「公式 pkg の手動導入を製品版の手順にする」と回答しました。導入後に OBS 再起動が必要であること、NDI Runtime が管理者認証を求める場合があることを示した質問への回答です。

### その他の導入方式

受諾対象の質問には、他の方式やその棄却理由が列挙されていません。自動導入などを会話で検討・棄却した案として追加することはできません。

## 適用範囲

- Apple Silicon 搭載 Mac における、製品版初回設定での DistroAV と NDI Runtime の手動導入案内。
- macOS の OBS から既存の NDI 受信経路へ映像を渡すための導入手順。

## 適用しない範囲

## 期待する効果

製品版の手順を、公式 pkg を利用者が手動導入する流れとして案内できます。導入・OBS 再起動・必要に応じた管理者認証を利用者が行う前提になります。

## 受け入れる欠点・リスク

- 利用者に pkg の入手と手動導入の作業が残ります。
- 質問中の説明どおりであれば、OBS の再起動が必要で、NDI Runtime の導入時に管理者認証が求められる場合があります。実際の対象バージョンでの要件は未確認です。
- pkg の導入完了だけでは、OBS の NDI 送出やアプリでの実映像受信が成立したとは判断できません。
- 公式 pkg の入手先と対応バージョンは未確定です。案内を製品化する時点で確認が必要です。

## 再検討条件

## ユーザー発言の原文

### 先行する NDI 入力方式の選択

assistant の質問（ordinal 12798）:

> OBS には MiraBox の映像がありますが、アプリの自動判定は NDI 映像を受け取る実装で、OBS 側の NDI 送出が未導入です。macOS の入力方式をどちらで進めますか？
> - DistroAV＋NDI Runtime を導入（現行実装に接続できる・推奨）
> - OBS 仮想カメラを判定入力に使う（追加プラグイン不要、アプリ改修と権限検証が必要）

user の回答（ordinal 12817）:

> DistroAV＋NDI Runtime を導入（現行実装に接続できる・推奨）

この方式選択の詳細は先行 ADR に記録されています。本 ADR では、導入方法に関係する経緯として参照します。

### 今回の導入方法の質問と回答

assistant の質問（ordinal 13014）:

> DistroAV と NDI Runtime の macOS 導入方法を決めます。公式 pkg の導入は OBS 再起動が必要で、NDI Runtime は管理者認証が必要になる場合があります。どの方針で進めますか？

user の回答（ordinal 13014）:

> 公式 pkg の手動導入を製品版の手順にする

質問前の assistant によるセットアップ判定の説明（ordinal 12977）:

> セットアップ判定にも修正が必要です。現在の「NDI 導入済み」は同梱ライブラリで受信器を開けたことを示すだけで、DistroAV が必要とする NDI Runtime や OBS の送出プラグインは確認していません。導入後に映像が届くまでを区別して判定できるようにします。

選択後の assistant による進行報告（ordinal 13021）:

> DistroAV と NDI Runtime は公式 pkg を手動導入する方針で進めます。まず既存のセットアップ判定と案内を確認し、導入から OBS 映像の受信確認まで対応します。
