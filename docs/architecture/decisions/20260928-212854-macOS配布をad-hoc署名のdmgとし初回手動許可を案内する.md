# macOS 配布を ad hoc 署名の dmg とし初回手動許可を案内する

- ID: 20260928-212854
- 状態: accepted
- 日時: 2026-09-28T21:28:54+09:00
- 判断者: ユーザー

## 目的・問題

Apple Silicon 向け macOS 版を GitHub Release から導入し、初回起動まで進めるため、アプリの署名・公証方式と配布形式を定める。macOS 対応計画ではこの選択をユーザー判断として留保していた。Windows の既存配布物は zip で、現在の macOS `.app` は ad hoc 署名済みだが、GitHub Release から取得した成果物による初回起動は未確認である。

## 前提・制約

- ユーザーは先行する確認で「全機能を同等に対応」「Apple Silicon のみ」と指定した。本 ADR はその範囲で M9 の配布方式を定め、機能範囲を変更しない。
- macOS 対応計画には、Windows 配布は zip、macOS の配布・署名・公証・初回起動は判断待ちと記録されていた。
- M8 の調査では arm64 `.app` の ad hoc 署名が確認されている。ローカルの起動結果は、ダウンロードした成果物の Gatekeeper の挙動を保証しない。
- Developer ID の保有状況、最低対応 macOS バージョン、各 macOS 版で必要となる具体的な手動許可手順は未確認である。
- Developer ID 署名・公証済みアプリが通常の初回起動に近い導線を提供する一方、年会費と証明書・公証の運用負担があること、ad hoc 署名では個別の起動許可が必要になることが選択前に説明された。ユーザーは ad hoc 方式を選んだが、費用以外を含む選択理由は明示していない。
- 現在の `.app` の署名状態と、配布用 dmg の署名状態は別の事項である。本 ADR は `.app` の ad hoc 署名を選び、dmg 自体の署名・公証や checksum の方式は定めない。

## 判断

1. Apple Silicon 向け macOS 版は ad hoc 署名の `.app` として配布する。現時点では Developer ID 署名と公証を採用しない。
2. GitHub Release の macOS 配布形式には dmg を使う。dmg 内の `.app` を Applications へ移して使う導入手順を示す。
3. 初回起動が macOS に止められた利用者向けに、システム設定で個別に許可する手順を案内する。画面名や操作文言など、OS の版に依存する具体的な説明は別途配布手順で確認する。
4. この判断は Apple Silicon 向け macOS の M9 配布に限る。Windows の zip 配布と既存機能の範囲は変更しない。

## 検討した選択肢と棄却理由

### 署名・公証

| 選択肢 | 判断と理由 |
| --- | --- |
| Developer ID で署名・公証する | 不採用。初回起動時の手動許可を避けやすい推奨案として提示された。Apple Developer Program の年会費は約 99 USD と説明された。ユーザーは ad hoc 署名を選んだ。費用が選択理由だったとは明示されていない。 |
| ad hoc 署名で配布し、手動許可を案内する | 採用。ユーザーの回答どおり。Developer ID を保有していない、または年会費を許容しないという判断までは含まない。 |

### 配布形式

| 選択肢 | 判断と理由 |
| --- | --- |
| zip | 不採用。既存の Windows 配布と同形式という案だった。技術上の不成立や zip 固有の欠点が示されたわけではなく、ユーザーが dmg を選んだため今回採用しない。 |
| dmg | 採用。ユーザーは「Finder で導入先を示しやすい」と理由を明示した。質問では zip / dmg のどちらでも `.app` を Applications に移して使う前提が示されていた。 |

選択肢は署名方式と配布形式の二つの軸で比較された。別の署名サービス、パッケージ形式、インストーラーは会話で比較されていないため追加しない。

## 適用範囲

- Apple Silicon 向け macOS アプリの GitHub Release 配布。
- 配布する `.app` の ad hoc 署名、dmg への格納、および初回起動時の手動許可案内。
- Applications へ `.app` を移す利用手順。

## 適用しない範囲

- Windows の zip 配布、Intel Mac、その他の OS。
- Developer ID 証明書の保有状況や会員登録の判断全般。この ADR が決めるのは今回の配布で Developer ID 署名・公証を使わないこと。
- dmg 自体の署名・公証、配布物の checksum、更新・自動更新方式。
- Application Support、Keychain、アプリ内 Homebrew など、インストール後のデータ・依存導入方式。
- 各 macOS の版で表示される設定画面名、初回起動の実機挙動、各機能の実機受け入れ。

## 期待する効果

- GitHub Release から取得する macOS 配布物を dmg にまとめ、Finder 上で Applications への導入先を示しやすくする。
- Developer ID の会費、証明書管理、公証処理を今回の配布の前提にせず、既存の ad hoc `.app` を使う方針を明確にする。
- 初回起動がブロックされた場合の手動許可を利用者へ案内する責務を明確にする。

## 受け入れる欠点・リスク

- 利用者に未確認開発元のアプリを個別に許可する操作が発生し、Developer ID 署名・公証を選ぶ場合より初回起動の負担が大きい。管理対象 Mac などでは組織のポリシーにより許可できない場合があるとの助言報告もある。
- ad hoc 署名は Developer ID による開発元の識別を提供しない。手動許可の案内だけで通常の初回起動を保証するものではない。
- macOS の版や端末の管理状態により手順が異なる可能性があるが、対象バージョンと実際の画面は未確認である。
- GitHub Release から取得した dmg の初回起動、通知・マイクなどの許可、更新後の Application Support / Keychain 維持は確認していない。署名済みローカル `.app` の起動確認を、これらの受け入れ確認とは扱わない。

## 再検討条件

- 手動許可が対象 macOS で成立しない、組織管理端末で配布できない、または利用者の初回起動負担が許容できないと分かった場合は、Developer ID 署名・公証へ移る条件と費用をユーザーに示して再確認する。
- GitHub Release から取得した dmg を使うクリーン環境の初回起動または Applications への導入が成立しない場合は、パッケージまたは手順を再検討する。
- macOS のサポート対象、Apple の配布要件、Developer ID の費用・運用条件が変わった場合。
- ユーザーが署名方式または配布形式の変更を求めた場合。

## 関連する設計指針

## ユーザー発言の原文

### macOS 対応の目的（親トランスクリプト ordinal 8）

> このアプリがmacでも正常動作することを目標として取り組んでください。\
> まずは対応が必要な機能を一覧化してください。\
> 次に対応方針を整理し、サブエージェント(astra・軽)にアドバイスをもらってください。\
> そしたら、どの順番で取り掛かるかまでをファイルに永続化して私に報告してください。\
> ユーザー影響や影響が大きい判断が必要な時は私に聞いてください。

### 適用範囲を確認した質問と回答（親トランスクリプト ordinal 172、182）

親エージェントの質問:

> 対象を確定するため、**Apple Silicon のみか Intel Mac も含むか**、**初回から全機能を同等にするか主要導線を先行するか**の回答をお願いします。

ユーザーの回答:

> 全機能を同等に対応\
> Apple Silicon のみ

### 署名・公証と配布形式を確認した質問（親トランスクリプト ordinal 11663）

> macOS 配布には Apple Developer Program の Developer ID 署名と公証を使いますか？ 年会費は約 99 USD です。使わない場合、利用者がシステム設定で未確認開発元のアプリを個別に許可する必要があります。
> - Developer ID で署名・公証する（推奨）
> - ad hoc 署名で配布し手動許可を案内する
>
> macOS の GitHub Release 配布形式はどちらにしますか？ どちらも `.app` を Applications に移して使います。
> - zip（既存の Windows 配布と同形式・推奨）
> - dmg（Finder で導入先を示しやすい）

### ユーザーの確定回答（親トランスクリプト ordinal 11690）

> ad hoc 署名で配布し手動許可を案内する\
> dmg（Finder で導入先を示しやすい）

ordinal 11695 の「M9 は ad hoc 署名の `.app` を dmg で配布し、初回起動時の手動許可を案内する方針で進めます」は親エージェントの要約であり、ユーザーの原文とは区別した。
