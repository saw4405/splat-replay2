# 設定ダイアログの視認性を構造と狭幅リフローで改善する

- ID: 20260810-174636
- 状態: accepted
- 日時: 2026-08-10T17:46:36+09:00
- 判断者: ユーザー

## 目的・問題

設定ダイアログについて、暗色テーマを一律に明るくするのではなく、情報階層、表示密度、狭幅でのリフロー、状態の伝達方法を改善し、設定項目と操作対象を把握しやすくします。

実画面レビューでは、主因として次が確認されました。

- 390px 幅で、タブが必要とする幅 453px に対して表示可能幅が 275px しかなく、設定本文にも横スクロールが発生し、入力欄が 156px まで縮小していました。
- 録画タブは表示領域 496px に対して内容が 1,877px あり、`panel → fieldset → field-item` の多重な面・枠・余白によって、一画面に見える項目数と主要グループの判別性が低下していました。
- 「推奨」、Boolean の状態、未表示項目の存在が、色、ノブ位置、細いスクロールバーなど限られた視覚手掛かりに依存していました。
- 項目が少ないタブでも高さが大きく固定され、内容量とダイアログの大きさが一致していませんでした。
- 見た目はタブですが、ARIA のタブ契約とキーボード操作がありませんでした。

## 前提・制約

- 設定カテゴリは既存の 5 タブを維持します。
- 録画タブの既存区分「キャプチャデバイス／OBS接続／録画／文字起こし」を維持します。
- カード装飾を減らしても、見出し、`section`、`fieldset`、`aria-labelledby` などの意味構造は失いません。
- 共通 `BaseDialog` の既定値は一括変更せず、内容適応高さは `SettingsDialog` に限定します。
- 説明文と非選択タブは、コード値からの概算では WCAG AA のコントラストを満たす可能性が高いものの、グラデーションと透過面を含む実画面ピクセルでの確定値は未確認です。
- ユーザーが録画設定を上から順に確認することが多いか、特定区分へ直接移動することが多いかは未確認です。

## 判断

設定ダイアログの視認性改善は、次の順序と境界で行います。

1. 640px 以下では既存の全画面ダイアログ機能を使い、5 タブを「3＋2」の 2 段グリッドへリフローします。本文とカードの余白を 12〜16px に縮小し、横スクロールと入力欄の過度な縮小を解消します。
2. 録画タブを、単一の面の中に「キャプチャデバイス／OBS接続／録画／文字起こし」の 4 区分と行区切りを置く構造へ簡素化します。
3. 「推奨」は色だけに依存せず、可視テキストの「推奨」バッジを併記します。
4. Boolean 設定は、広幅では説明を左、`オン／オフ` の状態文言とスイッチを右に置き、狭幅では縦積みに戻します。状態文言はネイティブ checkbox の `checked` 契約を置換せず、視覚上の補助として同期させます。
5. 未表示項目の手掛かりとして、太めで十分なコントラストのスクロールバー thumb と、スクロール終端で消える下端フェードを追加します。フェードは `pointer-events: none` とし、構造改善の代替にはしません。
6. 項目数が少ないタブの過大な空白を減らすため、設定ダイアログだけを内容適応高さかつ上限 90vh とします。
7. レイアウト変更と同時に `tablist`、`tab`、`tabpanel`、選択状態、矢印キー操作を実装し、視覚表現とタブの操作契約を一致させます。

説明文、非選択タブ、境界線などの視認性トークンは一律に引き上げません。意味のある境界だけを実画面で再測定したうえで必要なら調整します。

録画タブ内のコンパクトなセクション索引は候補に留め、今回の確定判断には含めません。

## 検討した選択肢と棄却理由

### 設定専用ワークスペースへ移す理想案

カテゴリと録画内セクションを常時表示し、長大な設定をモーダルの高さ制約から解放できます。しかし、現行ダイアログからの変更範囲と移行費用が大きいため、今回の実装対象には採用しませんでした。

### 現行ダイアログを維持し、構造とリフローを改善する案

内容適応高さ、単一面と 4 区分、2 段タブ、状態の可視テキスト化、スクロール手掛かり、ARIA タブ契約を組み合わせる案です。確認された根本原因を現行構造の範囲で解けるため採用しました。

### 全視認性トークンを一律に明るくする案

説明文と非選択タブは概算上すでに AA を満たす可能性が高く、多重面と横オーバーフローを解消しません。意味の階層も弱めうるため採用しませんでした。

### 狭幅でカテゴリを select に置き換える案

5 カテゴリの一覧性と直接移動を失い、現在有効な UI 設計 SSoT のタブ方針からも外れるため採用しませんでした。

### sticky 見出しだけで録画タブを改善する案

現在の区分は示せても、未閲覧区分の全体像や多重面による低密度を解消しないため、単独案として採用しませんでした。

### 録画タブ内にコンパクトなセクション索引を設ける案

未閲覧区分を常時示し、直接移動しやすくする候補です。ただし、上から順に確認するか特定区分へ直接移動するかという利用頻度が未確認であり、ユーザーが受諾した実装列挙にも含まれていないため、今回の判断には含めませんでした。

## 適用範囲

- `SettingsDialog` の狭幅レイアウト、内容高さ、スクロール手掛かり。
- 設定カテゴリのタブ表現とキーボード操作。
- 録画タブの視覚階層と表示密度。
- 設定項目における「推奨」と Boolean 状態の可視表現。

## 適用しない範囲

- 共通 `BaseDialog` の既定レイアウトの一括変更。
- 設定ダイアログを専用ワークスペースへ移すこと。
- 録画タブ内のセクション索引の採否。
- モーダルのフォーカストラップ、初期フォーカス、Escape 操作の見直し。これは今回の視認性変更と分離して扱います。
- 設定値、保存契約、外部 API、永続データの変更。

## 期待する効果

- 390px 級の狭幅でも、設定カテゴリと本文を二方向スクロールなしで利用できます。
- 録画タブで主要 4 区分と項目の関係を把握しやすくなり、一画面あたりの情報量が増えます。
- 「推奨」と Boolean 状態が色や位置だけに依存せず伝わります。
- 内容が少ないタブでは不要な空白が減り、内容が多いタブでは未表示項目の存在が分かりやすくなります。
- タブの見た目、選択状態、キーボード操作、支援技術向け意味が一致します。

## 受け入れる欠点・リスク

- 画面幅に応じた 2 種類の配置と、タブのフォーカス移動を保守する必要があります。
- 下端フェードはスクロール位置との同期が必要で、消去条件を誤ると入力や終端を覆って見せるリスクがあります。
- 面と枠を減らす際に意味的なグルーピングまで失うと、視認性とアクセシビリティが逆に悪化します。
- Boolean の状態文言と checkbox の状態が同期しない不具合を防ぐ必要があります。
- 実画面コントラストが未測定の境界については、構造変更後に追加調整が必要になる可能性があります。

## 再検討条件

- 320〜390 CSS px 相当で横スクロール、情報損失、操作不能が残る場合。
- 実画面ピクセルで測定した主要テキストまたは操作部品のコントラストが WCAG AA を満たさない場合。
- 録画設定で特定区分へ直接移動する需要が高いと確認され、セクション索引の価値を判断できる場合。
- 設定カテゴリまたは項目数が増え、2 段タブやモーダル自体が一覧性を保てなくなった場合。その場合は設定専用ワークスペースを再検討します。
- W3C の適用仕様またはプロジェクトの UI 設計 SSoT が変更された場合。
