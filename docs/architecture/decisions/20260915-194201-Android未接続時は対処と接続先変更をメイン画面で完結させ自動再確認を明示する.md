# Android未接続時は対処と接続先変更をメイン画面で完結させ自動再確認を明示する

- ID: 20260915-194201
- 状態: accepted
- 日時: 2026-09-15T19:42:01+09:00
- 判断者: ユーザー（具体的な案内順序・表示維持はメインエージェントによる実装上の具体化）

## 目的・問題

SplatReplay を使いたいのに PC に接続できないユーザーが、次に何をすべきか、または何もせず待てばよいかを明確かつ簡潔に理解できるようにする。接続先の誤りも含めて対処を案内し、未接続画面内で接続先の変更まで完結させる。

## 前提・制約

- ヘッダーは状態によって高さを変えない。
- 接続状態には色付きの丸と状態名を併用する。直前のユーザー指定は「●PC未接続」「●PC接続確認中」「●PC接続済」である。
- 接続パネルは直前のユーザー指定で「PC接続設定」、閉じる操作は右上の × へ変更されている。
- 自動再確認は接続可否を調べる動作であり、PC の電源投入や SplatReplay の遠隔起動ではない。
- ユーザーの最後の目的説明を、本件を超える一般指針へ自動昇格しない。

## 判断

1. ヘッダーの再接続ボタンを削除する。自動再確認とパネルの手動再接続があるため、未接続時にもヘッダー高さを一定に保つ。
2. 未接続時はメイン画面で、ユーザーが順番に対応できる案内を表示する。接続先の誤りも原因候補に含め、案内の中から迷わず接続先を変更できるようにする。
3. メインエージェントによる具体化は、スクロール可能な案内で「1. PC の起動と SplatReplay の起動」「2. 同じ自宅ネットワークへの接続」「3. LAN アクセス URL と接続先の照合」の順とし、URL の直下に接続先変更の入口を置く。ユーザーがこの具体的順序を逐語的に指定したとは扱わない。
4. ユーザーが行う対処と、自動再確認についての説明を別段落にする。Android アプリの画面を開いたまま待てること、接続できない場合は自動で再確認すること、成功したら本体画面を自動表示すること、再接続ボタンを押す必要がないことを説明する。
5. 自動再確認を行う間も「●PC接続確認中」を表示する。メインエージェントは確認中を黄の丸で示し、未接続の対処案内を消さず維持する構成へ具体化した。
6. 今回の実装説明は「失敗から 5 秒後に再確認」である。先行回答の「5秒ごと」はユーザーが説明の明確化を求めた対象として保存し、確認処理時間も含めた厳密な固定周期や将来不変の設定値を新たに承認したとは扱わない。

## 検討した選択肢と棄却理由

| 選択肢 | 採否・理由 |
| --- | --- |
| ヘッダーの再接続ボタンに余白を付ける | 直前のユーザー依頼で採用したが、未接続時の高さ変化が報告された。最新指示でボタン自体を削除する方針へ変更。 |
| 接続設定パネルを開いて原因確認・接続先変更を行う | 未接続時の主導線として不採用。ユーザーがメイン画面の案内で完結させるよう明示した。パネル自体やその再接続操作は維持。 |
| 対処と自動再確認を一続きの文章で説明する | 不採用。性格が異なるため、別段落で表示するというユーザー指示。 |
| 接続先誤りも含む段階的な案内とその場での変更 | 採用。使えない状況で次の行動を迷わず選べるようにする。 |
| 自動再確認中も未接続の状態名のままとする | 不採用。試行時は確認中にする方が明示的で分かりやすいというユーザー指示。 |
| 再確認中も対処案内を維持する | メインエージェントによる具体化。案内の継続表示をユーザーが別途逐語的に承認したとは扱わない。 |

## 適用範囲

Android ラッパーの PC 未接続時の案内・接続先変更・自動再確認の説明と状態表示。関連する状態名とパネル名の先行訂正も、現在の UI を解釈する文脈として記録する。

## 適用しない範囲

PC の遠隔起動、Windows・OBS のライフサイクル、認証・通信仕様の追加、ユーザーが原因を確認する代わりの自動原因断定、本体 Web 画面の設計変更、再確認間隔の恒久固定。

## 期待する効果

ユーザーが順番に確認・修正し、その後は待つだけでよいと理解できる。接続先修正のために別パネルを探す負担と、状態変化によるヘッダーの高さ変化をなくす。

## 受け入れる欠点・リスク

- 接続先変更への入口がパネルと未接続画面の両方に存在する。
- 案内は原因候補の確認手順であり、特定の原因を自動診断した結果ではない。
- 自動試行のたびに確認中へ状態が切り替わる。表示の分かりやすさ、スクロール画面の使いやすさ、実機での結果は本 RECORD では未確認。
- 手順や具体的な 5 秒という説明は、実際の再確認動作が変われば一致を再確認する必要がある。

## 再検討条件

ユーザーが具体的な再検討条件を指定した事実はない。自動再確認動作や接続先設定導線が変わる場合は説明との整合確認が必要である。これは本記録の鮮度条件であり、新たなユーザー承認済み方針ではない。

## 関連する設計指針

登録済み指針はない。根拠は本件についてのユーザーの明示指示である。一般指針は追加しない。

## ユーザー発言の原文

先行する状態の視覚表現と利用者向け文言の依頼（1481 行、添付メタデータを除く依頼本文）:

> 接続状態は緑の●アイコンとかでも表現すると、より分かりやすいと思います。
> また、下から開いたパネルのタイトルと説明が、このチャットでの依頼内容を説明的に書いているのが気になります。Androidアプリのユーザーへ向けた適切な文言にしてください。

先行する状態名・ヘッダー・パネルの指定（1517 行）:

> 状態は以下にしてください。
> ●PC未接続
> ●PC接続確認中
> ●PC接続済
>
> 再接続ボタンがヘッダー領域に余白なく配置されているので、少し余白を入れてください。
>
>
> PC接続設定にしてください。
>
> パネルから閉じるボタンをなくし、代わりにパネル右上に×ボタンを用意してください。

自動再接続への質問（1569 行）:

> 自動で再接続を試みるとは？

最新依頼の「それ」が参照するメインエージェントの説明全文（1572 行）:

> Androidアプリを開いている間、**5秒ごとにPCのSplatReplayへ接続できるか確認する**という意味です。
>
> 接続できない間も確認を続け、PCやWi-Fiが復帰すると、自動で画面を読み込み直します。「再接続」ボタンは、次の確認を待たずにすぐ試すためのものです。
>
> PCの電源投入やSplatReplayの起動を遠隔で行う機能ではありません。

今回のユーザー指示全文（1579 行、2026-09-15T19:37:07+09:00）:

> それが分かるように書いて。
> 後、それ以前の文章とは性格が違うから改行して別物として表示した方がいい。
> PC未接続のとき、ヘッダー領域の高さが変わってしまう。再接続ボタンの余白を持たせるためだと思うけど、ヘッダー領域の高さは変えないでください。自動的にリトライするし、パネルにも再接続ボタンがあるから、ヘッダーには再接続ボタンいらない。
> 再接続を試みるとき、状態を確認中にしたほうが明示的にわかりやすい。
> 接続できない原因として、接続先の間違いもあると思う。
> ユーザーの対応を順番にできるように画面上で案内した方がいい。その中で例えば、接続先を確認して違うようなら、その案内の中で迷いなく変更できるようにしてください。(パネルと前述したけど、未接続のときはメイン画面の案内で完結できるようにしてください)
>
>
>
> 要するに、ユーザーはsplat replayアプリを使いたいのに使えない状況であれば、ユーザーが次に何をしたらいいのか(もしくは何もしなくていいのか)が明確かつ簡潔に分かるようにすべきです。ユーザーがsplat replayアプリを使うためのユーザー体験を考慮しましょう。
>

メインエージェントによる実装の具体化（1620 行）:

> 未接続時は「PCで起動 → 同じ自宅ネットワークに接続 → 接続先URLを照合」の順に案内し、URLのすぐ下から変更できるようにしました。自動再確認中も案内は消さず、ヘッダーの状態だけを「●PC接続確認中」に切り替えます。
>
