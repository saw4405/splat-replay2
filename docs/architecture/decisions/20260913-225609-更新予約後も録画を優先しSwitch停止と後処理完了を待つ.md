# 更新予約後も録画を優先しSwitch停止と後処理完了を待つ

- ID: 20260913-225609
- 状態: accepted
- 日時: 2026-09-13T22:56:09+09:00
- 判断者: ユーザー

## 目的・問題

更新予約後にも Switch で遊び続ける場合の優先順位を確定し、自動録画と更新開始の競合を解消する。

## 前提・制約

SplatReplay の常駐、自動録画、処理完了後の正常終了・更新・再起動は ADR `20260913-224011` に従う。同 ADR の判断 6 では更新予約後の優先順位が未確定だった。

## 判断

更新予約後も Switch のプレイと録画を優先し、新しいプレイの自動録画を更新のために抑止しない。Switch がスリープ／OFF と判定され、編集・アップロードも完了してから更新を開始する。

## 検討した選択肢と棄却理由

| 選択肢 | 採否と理由 |
| --- | --- |
| 録画を優先し、Switch のスリープと編集・アップロード完了を待つ | 採用。ユーザーが提示された推奨案を選択した。 |
| 進行中の録画・処理完了後は新しい録画を開始せず更新する | 不採用。更新予約後も録画を優先する今回の選択と両立しない。ユーザーによる追加の棄却理由は未確認。 |

## 適用範囲

常駐デスクトップ版 SplatReplay の更新予約から更新開始までの録画優先順位と待機条件。

## 適用しない範囲

Switch OFF 判定の実装、更新状態機械・失敗処理・取消の詳細、Android 接続方式、OBS の終了所有権、起動時未処理動画の扱い。本判断は仕様案全体や実装の包括的承認ではない。

## 期待する効果

更新予約を理由にプレイ中の自動録画機会を失わず、後処理完了後に更新へ進める。

## 受け入れる欠点・リスク

遊び続ける場合や編集・アップロードが完了しない場合、更新開始が遅れる。待機期限や強制更新の例外は本判断では定めない。実装・実機動作は未確認である。

## 再検討条件

ユーザーが更新の期限や録画より更新を優先する例外を必要とした場合。本条件は記録上の再検討目安であり、例外動作の承認ではない。
