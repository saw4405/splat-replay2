# macOS では独自フォントを任意とし、キャプチャ機器を表示名で扱う

- ID: 20260928-081151
- 状態: accepted
- 日時: 2026-09-28T08:11:51+09:00
- 判断者: ユーザー

## 目的・問題

Apple Silicon 向け macOS 対応で、サムネイル用の「イカモドキ」フォントが見つからない場合の扱いと、同じ表示名を持つキャプチャ機器の選択方式を決める必要がありました。会話中の検証報告では、`ikamodoki1.ttf` がない標準設定でサムネイル生成が止まっていました。また、macOS で同名機器を個別に選ぶ方式と、Windows 版と同じ表示名保存方式のどちらを採用するか質問されていました。

## 前提・制約

- 先行するユーザー判断は、macOS で「全機能を同等に対応」、対象を「Apple Silicon のみ」とするものです。
- 会話中の検証報告は、`ikamodoki1.ttf` が検証環境にないと標準設定のサムネイル生成が止まる、としています。これは当時の assistant による実行報告であり、本 ADR 作成時にサムネイル生成経路を再実行した結果ではありません。
- 作者の公式ページは、「イカモドキ」の公開終了と、現在インターネット上でダウンロード可能なフォントファイルが作者の許可を得ていない二次配布であることを明記しています。Wayback 上の保存物を正規の現行配布経路として扱わないのは、この記載に基づく判断上の整理です。
- 会話中の Windows 版に関する調査・質問では、キャプチャ機器設定は表示名を保存すると報告されています。同じ表示名だけを保存する方式から、同名の複数機器を個別に選択・永続識別できないことは導けます。実際の macOS 機器列挙と接続判定は、この ADR 作成時点で未確認です。
- 同名機器が複数ある場合の一覧表示・接続判定の細かな挙動は、ユーザー発言では指定されていません。

## 判断

1. `ikamodoki1.ttf` を必須依存にしません。対象フォントがない場合は OS 標準フォントを使用します。具体的なフォントファミリーは未確認です。
2. macOS のキャプチャ機器設定は、既存 Windows 版と同じ表示名保存方式を維持します。機器ごとの一意 ID を設定値として保存する方式へは変更しません。
3. 表示名が同じ機器を個別に選択・識別できない制約を受け入れます。この判断は、同名時の接続判定や UI の詳細な振る舞いまでは定めません。

## 検討した選択肢と棄却理由

### 対象フォントがない場合に利用者の保有フォントを必須にする

ユーザーは対象フォントをオプション扱いにし、ない場合は OS 標準フォントを使うよう指定しました。必須配置方式は採用しません。

### 別の再配布可能なフォントを同梱する

選択肢として提示されましたが、ユーザーは対象フォントがない場合の OS 標準フォント使用を指定しました。別フォントの選定・同梱は本判断に含めません。

### 同名機器を個別に選ぶため識別子を保存する

会話では同名機器の個別選択が推奨案として提示されました。ユーザーは同名機器があっても現在の方式で続けてよいと回答し、直後の assistant も既存の表示名方式を維持すると確認しました。個別識別案を採用しない理由の詳細は、ユーザーから明示されていません。

### Windows 版と同じ表示名を保存する

既存方式を維持する選択肢です。ユーザーの回答を受け、本 ADR の判断として採用します。同名機器が個別に区別できない制約を伴います。

## 適用範囲

- Apple Silicon 向け macOS 版のサムネイル生成における `ikamodoki1.ttf` の必須性と、未配置時のフォント選択。
- macOS 版のキャプチャ機器設定における保存値の識別単位。
- Windows 版と共通する表示名保存方式を macOS でも維持する判断。

## 適用しない範囲

- OS 標準フォントの具体的な名称、文字カバレッジ、サムネイル上の視覚的な同一性。
- 利用者が任意に所有する対象フォントの導入方法や配置先。
- 同名機器が列挙された場合の表示、選択 UI、接続判定の詳細。
- macOS 上の実機キャプチャ・権限・切断監視の動作保証。
- USB 機器の自動復旧。これは既存 ADR `20260927-162930` の判断対象であり、本 ADR は変更しません。

## 期待する効果

- 作者が公開を終了したフォントを必須とせず、フォントがない環境でも OS 標準フォントでサムネイル生成を続けられます。
- macOS 用にキャプチャ機器設定の識別方式を変更せず、Windows 版と表示名保存の契約を揃えられます。

## 受け入れる欠点・リスク

- OS 標準フォントでは、対象フォント使用時とサムネイルの見た目が異なる可能性があります。レイアウト差や全対象文字の描画可否は未確認です。
- 同名機器は保存値から個体を区別できません。誤った機器を選ばないことや同名時の接続判定を保証しません。
- macOS 実機でのフォント描画、機器列挙、権限状態、抜線後の検知は、この設計判断の確定によって検証済みにはなりません。

## 再検討条件

- サムネイルの視覚的一貫性が必須となり、OS 標準フォントでは要件を満たさないことが確認された場合。
- 作者が正規に利用できるフォント配布元または明確な再配布許諾を再開した場合。
- 同名機器を個別に選択・維持する要求が生じた場合、または表示名方式で誤選択が発生した場合。
- macOS 実機で同名時の列挙・接続判定の実装を確定する必要が生じた場合。

## 関連する設計指針

登録済みの設計指針はありません。今回の判断は macOS サポートにおける個別のフォント・機器設定であり、一般化した指針は新設しません。

## 置換・追補関係

既存 ADR の置換はありません。`20260913-013343` が定めた、利用者配置の `assets/thumbnail/ikamodoki1.ttf` を更新時に保持し配布物に同梱しない判断を維持します。本 ADR は、同フォントが未配置の場合に OS 標準フォントへフォールバックする扱いを追補します。加えて、`20260927-153139` が定めた Apple Silicon 向け全機能同等の範囲に、キャプチャ機器の表示名保存方式を追補します。`20260927-162930` の USB 機器自動復旧除外はそのまま維持し、意味を変更しません。

### macOS 対応の目的と範囲

user（ordinal 8）:

> このアプリがmacでも正常動作することを目標として取り組んでください。
> まずは対応が必要な機能を一覧化してください。

>

user（ordinal 182）:

> Apple Silicon のみ

### サムネイル用フォント

assistant の検証報告（ordinal 7776）:

> 編集経路の実検証では、一時コピーからの結合、字幕ファイル生成、サムネイル描画、MKV への画像埋め込みが成功し、元録画も不変でした。一方、実アプリ指定の `ikamodoki1.ttf` がこの環境にないため、標準設定ではサムネイル生成が止まります。見た目と導入方法に影響するので、設計助言を確認してから選択肢を提示します。

assistant の質問（ordinal 7811）:

> サムネイル用「イカモドキ」は作者が公開を終了し、現在のダウンロードファイルは無許可の再配布と案内しています。macOS で未導入の場合、どの方式にしますか？
> - Mac 標準の日本語フォントへ自動切替（推奨）
> - 利用者が保有するイカモドキの配置を必須にする
> - 再配布可能な別フォントを同梱する

### キャプチャ機器

assistant の質問（ordinal 8232）:

> macOS のキャプチャ機器選択は、同名の機器を個別に選べる必要がありますか？ 現在の Windows 版は表示名を保存しています。
> - 同名機器も個別に選ぶ（推奨）
> - Windows と同じ表示名方式でよい

user の回答（ordinal 8360）:

> 対象フォントをオプション扱いとし、そのフォントがない場合はOS標準フォントを使ってください。
> 同名キャプチャ機器があってもそのまま継続でいいです

assistant の直後の確認（ordinal 8365）:

> 方針を確定しました。イカモドキは任意にし、ない場合は macOS の日本語フォントを使います。キャプチャ機器は既存の表示名方式を維持し、同名機器もそのまま扱います。両作業を完了条件付きで Luna サブエージェントへ委譲し、私が差分と実機検証を確認します。
