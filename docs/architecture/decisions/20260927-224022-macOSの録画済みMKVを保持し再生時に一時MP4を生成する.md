# macOS の録画済み MKV を保持し再生時に一時 MP4 を生成する

- ID: 20260927-224022
- 状態: accepted
- 日時: 2026-09-27T22:40:22+09:00
- 判断者: ユーザー

## 目的・問題

macOS のアプリ内 WebView で録画済み MKV を再生・シークできるようにしつつ、録画方式を維持する方針を決めます。ユーザーはまず Windows と同じように MKV を直接再生できるか確認するよう求めましたが、会話内の実録画検証では現行配信ルートからデータを受け取った後に WebView が再生エラーを返しました。その結果を受け、ユーザーは録画済み MKV を維持し、再生時に MP4 を一時生成する案を選びました。

## 前提・制約

- 先行する macOS 対応判断では、対象は Apple Silicon、対応目標は全機能同等とされています（関連 ADR `20260927-153139`）。
- 実録画の検証前に行った対照試験について、会話内の報告では、この Mac の WKWebView でテスト用 H.264 MKV は直接再生できず、同じ映像を入れた MP4 は再生・シークできたとされています。これはテスト用サンプルの結果です。
- 会話内の検証報告によると、ムービーフォルダにあった実際の OBS 録画は H.264/AAC、1080p/60fps、約 6.1 秒の MKV でした。現行の動画配信ルートではデータを取得できましたが、macOS WebView は `MediaError.code=4` を返し、再生・シークできませんでした。
- 同じ検証報告では、添付ファイル指定を外す、MIME type を変える、という変更でも結果は変わらず、元録画の前後 SHA-256 は一致したとされています。本 RECORD では実機検証を再実施していません。
- 検証は配信ルートと動画 UI に近い条件で行われ、配布 `.app` の画面全体を通した確認は未実施と報告されています。
- 実録画を MP4 にする際に再エンコードが必要か、所要時間・容量、キャッシュ方式、一時ファイルの保存先と削除時点、変換失敗時の表示は未確認です。

## 判断

1. macOS の録画済み MKV は録画ファイルとして保持します。再生用 MP4 を作る処理で元 MKV を上書き・置換しません。
2. macOS アプリで録画済み MKV の再生が要求されたとき、再生用 MP4 を一時生成して再生に使います。
3. 新規録画方式を Hybrid MP4 へ変更する判断は採用しません。録画方式は MKV のまま維持します。
4. 再生用 MP4 で実際に再生とシークが成立することを実装後の期待条件とします。この成功は本 ADR 作成時点では未確認です。

## 検討した選択肢と棄却理由

ordinal 6418 の比較では、どちらの案でも既存 MKV は残せ、違いは新規録画形式だと説明されています。以下の外部仕様に関する説明は会話内の比較として記録し、本 RECORD では独立に検証していません。

### MKV をそのまま再生する

ユーザーは Windows と同じ再生経路が macOS でも可能か確認するよう求めました。会話内の報告では、テスト用 H.264 MKV は直接再生できず、同じ映像の MP4 は再生・シークできました。続く実録画の検証でも現行配信ルートにおいて `MediaError.code=4` となりました。今回の Mac の WKWebView と実録画の組み合わせでは成立しなかったため、この経路を再生方針として採用しません。ほかの macOS/WebView の組み合わせやすべての MKV 形式について一般化した結果ではありません。

### MKV 録画を維持し、再生時に MP4 を一時生成する

ユーザーが選択した方式です。会話内の比較では、録画方式を変えずに元 MKV を保全できる一方、初回再生の待ち時間と一時容量が必要で、形式の組み合わせによっては再エンコードが必要と説明されました。MP4 のコーデック、変換方式、キャッシュおよび削除条件は未確定です。

### 新規録画を Hybrid MP4 に変更する

会話内の比較では、新規録画用の再生コピーを作らずに済む可能性と、OBS の Hybrid MP4 は異常終了後の復旧を想定した形式だという説明が利点として挙げられました。一方、録画設定や編集・一覧処理の検証が必要で、既存 MKV には引き続き別対応が必要なこと、MP4 でも WebView が非対応のコーデックなら再生できないことが欠点として示されました。ユーザーは録画を MKV のまま維持する案を選んだため採用しません。

## 適用範囲

- 対象 macOS 環境で、アプリ内再生の対象となる録画済み MKV。
- 元 MKV を保持したまま再生用 MP4 を一時生成する方針。
- 新規録画形式を MKV のまま維持すること。

## 適用しない範囲

- Windows の再生方式、Windows での録画形式。
- 編集済み動画の形式・再生変換、アップロードする成果物の形式。
- 再生用 MP4 の具体的なコンテナ・コーデック選択、再エンコード要否、品質設定。
- キャッシュ、同時再生、保存場所、削除タイミング、容量上限、変換失敗時の UI 契約。
- 配布 `.app` 全体での動作保証、およびすべての MKV コーデック・音声形式への対応保証。

## 期待する効果

- 元の録画済み MKV を保全しながら、macOS アプリで再生互換性のある MP4 を用いた再生経路を設けられます。
- 新規録画の形式を変える判断や、それに伴う録画・編集・一覧処理の変更を今回の再生対応から切り離せます。

## 受け入れる欠点・リスク

- MP4 の生成完了まで初回再生が遅れる可能性があります。
- 再生用ファイルが存在する間、追加のディスク容量を使います。必要容量の見積もりは未確認です。
- 映像・音声形式によっては再エンコードが必要となり、待ち時間、CPU 使用量、出力品質に影響する可能性があります。
- 一時ファイルの削除・再利用方法が未確定のため、実装時に後片付けと変換失敗時の元 MKV 保全を具体化する必要があります。
- 実録画の再生・シークと、配布 `.app` の画面全体での成功は未確認です。

## 再検討条件

- 再生用 MP4 でも実録画の再生・シークが成立しないことが確認された場合。
- 変換の待ち時間、必要容量、再エンコードの負荷が利用上許容できないと確認された場合。
- 一時ファイルの後片付けや再利用で、元録画の保全または容量管理を満たせない場合。
- 対象 macOS/WebView で実録画の MKV 直接再生が成立するようになり、再生時変換を外す利点が確認された場合。
- 対象プラットフォーム、対応コーデック、録画方式の方針が変わる場合。

## 調査した根拠

### 会話内の一次情報

- ordinal 6418 に、MKV 維持＋再生時 MP4 生成と新規録画を Hybrid MP4 にする二案の比較があります。assistant は [OBS Hybrid MP4 の説明](https://obsproject.com/kb/hybrid-mp4) と [Apple WebKit の動画配信指針](https://developer.apple.com/documentation/webkit/delivering-video-content-for-safari) にも触れています。異常終了時の復旧設計と静的動画向け H.264 MP4 の説明は会話中の比較として扱い、本 RECORD では外部仕様を独立に検証していません。
- ordinal 6425 で、ユーザーはムービーフォルダ内の実際の OBS 録画を動作テストに使うよう依頼しています。
- ordinals 6671、6710 の assistant 検証報告に、実録画の形式、再生エラー、添付指定・MIME type 変更での結果、元ファイルのハッシュ不変、検証範囲が記されています。本 RECORD では実録画やログを再確認していません。
- `docs/architecture/decisions/README.md`: RECORD の原文併記、会話カバレッジ、セルフレビュー、書き込み範囲を確認しました。
- `docs/architecture/principles/README.md`: 登録済み設計指針がないことを確認しました。
- 関連 ADR `20260927-153139`: macOS の対象 CPU と対応目標を確認しました。
