# 設定ダイアログの外形を固定し表示構造を保存元から分離する

- ID: 20260811-191426
- 状態: accepted
- 日時: 2026-08-11T19:14:26+09:00
- 判断者: 共同

## 目的・問題

設定タブを切り替えたときにダイアログの外形が変わると、画面上の基準位置と操作対象が移動します。また、表示タブでは API の保存元である `webview` / `remote_access` をそのまま可視グループにしたため、動作・編集・アップロードの各タブと異なる不要な階層が生まれていました。

設定の保存先を維持しながら、表示タブを通常のフィールド一覧として扱い、タブ間で安定した外形と一貫した情報密度を得ます。録画タブに残す意味のある区分については、区分見出しとカード枠線が重ならない構造にします。

## 前提・制約

- 設定カテゴリの既存 5 タブは維持します。
- 表示タブの `webview` と `remote_access` は保存時の所有境界であり、それ自体を可視グループにする要件ではありません。
- 表示タブのフィールドは、保存時に元の `webview` / `remote_access` へ正しく再分割する必要があります。
- 表示タブは、グルーピングされていない動作・編集・アップロードと同じ通常のフィールド一覧にします。
- 録画タブの現在有効な表示区分は、ADR `20260811-111359` で確定した「キャプチャデバイス／OBS接続／文字起こし」の 3 区分です。`record` / `RecordSettings` は新規公開しません。
- 旧 ADR `20260810-174636` は `accepted` であるため、直接修正せず、本 ADR から必要箇所だけを部分置換・追補します。
- 共通 `BaseDialog` の既定レイアウトを一括変更しません。

## 判断

1. 設定ダイアログの外形はタブ間で固定し、タブごとの内容量の差はダイアログ内部のスクロールで扱います。設定ダイアログは上限・下限ともに `90vh` とし、狭幅では既存の全画面表示を維持します。
2. UI 上の表示構造と API 上の保存元セクションを分離します。UI 専用の `SettingsUiField` に `sourceSectionId` を持たせ、可視構造とは独立して各フィールドの保存元を保持します。
3. 表示タブは `webview` / `remote_access` のグループを最初から生成せず、両セクションの編集可能フィールドを平坦な通常フィールドとして並べます。「描画モード」と「LAN 公開」はグループ見出しではなく各フィールド自身のラベルとして表示します。
4. 保存時は `sourceSectionId` ごとに値を再集約し、`webview` と `remote_access` の更新セクションへ分割します。表示の平坦化によって保存契約を変更しません。
5. 表示は `flat`、録画だけは `sectioned` とします。意味のある可視グループを持つ録画タブでは、見出しをカード境界上の `legend` として重ねず、グループ内の見出しとして配置し、グループ名のアクセシブルな関連付けを維持します。
6. LAN 公開の補足情報は非表示グループの付加領域に依存させず、`remote_access` の通常フィールド群に続く表示タブの内容として配置します。
7. 異なる保存元に同名フィールドが存在しても表示・更新・保存が衝突しないよう、UI 上の識別には `sourceSectionId` とフィールド ID の組を使います。

## 検討した選択肢と棄却理由

### 保存元ごとのグループを生成してから見出しと枠だけを隠す

見た目は平坦になりますが、DOM と UI データ構造には不要なグループが残り、通常フィールド一覧という要件を満たしません。LAN 公開の補足表示も非表示グループへ依存し続けるため、明示的に棄却しました。

### 表示タブを平坦化し、全フィールドを一つの保存セクションとして送る

表示構造は単純になりますが、`webview` / `remote_access` の保存契約を壊します。表示上のまとまりと保存上の所有権を混同するため採用しませんでした。

### API側で `webview` と `remote_access` を一つのセクションへ統合する

UI の不要な階層を取り除く目的に対して、API・永続化まで変更範囲を広げます。現在の保存境界を変更する必要はないため採用しませんでした。

### UI専用フィールドに保存元を持たせ、表示だけを平坦化する

通常フィールド一覧と既存の保存契約を両立し、変更責務を UI の変換境界へ限定できます。録画タブの意味ある区分も維持できるため採用しました。

### タブ内容に合わせてダイアログの高さを適応させる

内容が少ないタブの空白は減りますが、タブ切替ごとに外形と基準位置が変化します。ユーザーが外形を変えないことを明示したため、旧判断を撤回して採用しませんでした。

### 録画区分の見出しをカード境界上に置く

区分名と枠線が視覚的に重なります。見出しをカード内部へ置いて意味的関連付けを保つ方が、区分と内容を安定して読めるため採用しませんでした。

## 適用範囲

- `SettingsDialog` のタブ間での外形、高さ制約、内部スクロール。
- 設定 UI 用のセクション・フィールド変換と保存元の追跡。
- 表示タブの平坦なフィールド一覧、LAN 公開の補足表示位置。
- 録画タブに残る可視グループの見出し配置。
- 旧 ADR `20260810-174636` の内容適応高さと、意味構造に関する適用境界の部分置換・追補。

## 適用しない範囲

- API の設定セクション、永続化形式、`user_editable` 契約の変更。
- `record` / `RecordSettings` の新規公開。
- 録画タブの 3 区分を選ぶ判断。これは ADR `20260811-111359` をそのまま維持します。
- 動作・編集・アップロードの設定内容または保存契約の変更。
- 共通 `BaseDialog` の既定値の一括変更。
- 旧 ADR にある狭幅リフロー、推奨表示、Boolean 状態文言、スクロール手掛かり、ARIA タブ契約の変更。

## 期待する効果

- タブ切替時にダイアログ外形と操作の基準位置が変わりません。
- 表示タブが他の非グループタブと同じ通常フィールド一覧になり、不要な見出しと枠がなくなります。
- UI 上の情報構造を簡素化しても、値を `webview` / `remote_access` へ正しく保存できます。
- 録画タブでは区分見出しがカード枠線と重ならず、区分名と内容の関係を保てます。
- 将来、異なる保存元に同名フィールドが増えても、UI 上の識別と保存先が衝突しにくくなります。

## 受け入れる欠点・リスク

- 項目が少ないタブでは、固定外形の内部に空白が残ります。
- UI 専用フィールドに `sourceSectionId` を保持し、表示構造とは別に保存時の再集約処理を保守する必要があります。
- `sourceSectionId` の付与漏れや誤りは、値を誤ったセクションへ保存する原因になります。
- LAN 公開の補足情報は通常フィールドの後に描画するため、フィールド順序の変更時に配置条件も確認する必要があります。
- 可視グループと保存元セクションを同一視しないため、両者の違いを型と命名で明確に保つ必要があります。

## 再検討条件

- 設定カテゴリ数または項目数が増え、固定 `90vh` のモーダルでは一覧性や操作性を保てなくなった場合。
- API が UI 用の明示的なレイアウトまたはグルーピング情報を提供する契約へ変わった場合。
- `webview` / `remote_access` の保存境界自体を統合または変更する場合。
- 表示タブにユーザーが意味を認識できる新しい区分が必要だと確認された場合。
- `record` / `RecordSettings` の公開判断または録画タブの表示区分が変更された場合。

## 調査した根拠

### リポジトリ内の一次情報

- `frontend/src/main/components/settings/grouping.ts`: `SettingsUiField` が `sourceSectionId` を持ち、表示は `flat`、録画は `sectioned` として変換します。保存時は `sourceSectionId` ごとに値を再集約します。
- `frontend/src/main/components/settings/SettingsDialog.svelte`: 各フィールドを `sourceSectionId` とフィールド ID の組で識別し、LAN 公開の補足を `remote_access` の通常フィールド群に続けて描画します。設定ダイアログは `maxHeight="90vh"` と `minHeight="90vh"` を指定し、内容領域を内部スクロールさせます。
- `frontend/src/main/components/settings/FieldItem.svelte`: 可視グループは `role="group"` と内部の `h3` を関連付け、見出しをカード境界上に重ねません。
- `frontend/src/main/components/settings/grouping.test.ts`: 表示タブをグループなしで平坦化しながら、保存更新を `webview` / `remote_access` へ分割する契約を確認します。
- [旧 ADR `20260810-174636`](./20260810-174636-設定ダイアログの視認性を構造と狭幅リフローで改善する.md): 内容適応高さと意味構造に関する旧判断。
- [録画区分訂正 ADR `20260811-111359`](./20260811-111359-録画タブの表示区分をAPIの編集可能設定に合わせる.md): 現在有効な録画 3 区分と `record` 非公開の境界。
- [設計判断の実行契約](./README.md): 採用済み ADR は直接変更せず、新 ADR から部分置換・追補関係を記録します。

外部仕様や学術的知見は、今回の内部 UI view model、保存変換、固定外形の明示的なユーザー判断を補う外部契約ではないため、追加調査していません。

## ユーザー発言の原文

ユーザーは、外形、表示タブの区切り、録画タブの見出し配置について次のように指示しました。

> タブの選択状態によって設定ダイアログのサイズを変えないでください。
> 表示タブの表示とLAN公開区切りはなくして、描画モードとLAN公開のラベルがあればいい
> キャプチャデバイス／OBS接続／録画／文字起こし区切りがカードの枠線と重なっているので改善してください

メインエージェントは、当初の実装範囲を次のように解釈しました。

> 3点とも反映します。成功条件は、タブ切替でダイアログ外形が変わらないこと、表示タブ内は「描画モード」「LAN公開」のラベルだけで区分すること、録画タブの4見出しがカード枠線と重ならないことです。テスト選定に `test-ops`、実画面確認にブラウザ操作スキルを使用し、既存の未コミット変更を保ったまま進めます。

この解釈による最初の実装は、表示用グループを残して見出しと枠を隠す構造でした。ユーザーは、それを次の原文で明示的に訂正しました。

> 表示タブは、グルーピングされていない他のタブ（動作・編集・アップロード）と同じ通常のフィールド一覧として実装してください。webview / remote_access のグループを生成してから見出しや枠を隠す対応にはせず、最初から表示用グループを作らないでください。

受領後、メインエージェントは解釈を次のように明示しました。

> 承知しました。表示タブは見た目だけ平坦化するのではなく、データ構造上も `webview` / `remote_access` のグループを生成しない通常フィールド一覧へ変更します。これは保存時に2つの元セクションへ正しく戻す責務に関わるため、プロジェクト規約どおり `design_steward` の助言を確認してから最小構成で実装します。先ほどのコンポーネントテストは160件すべて成功済みです。

設計助言後、採用する責務分離を次のように明示しました。

> `design_steward` の助言では、APIの `SettingField` 自体は変えず、UI専用フィールドに所有元の `sourceSectionId` を持たせる構成が適切です。表示はflat、録画だけsectionedとし、保存は所有元ごとに再集約します。この方針なら見た目の隠蔽を完全に削除しつつ、`webview` / `remote_access` の保存契約も維持できます。これに沿って実装します。

録画タブの現在有効な 3 区分は、先行する次のユーザー原文と ADR `20260811-111359` に従います。

> 録画タブの設定は「キャプチャデバイス／OBS接続／文字起こし」の3区分が正しいですね。
