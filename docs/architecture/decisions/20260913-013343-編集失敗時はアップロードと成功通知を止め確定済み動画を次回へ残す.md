# 編集失敗時はアップロードと成功通知を止め確定済み動画を次回へ残す

- ID: 20260913-013343
- 状態: accepted
- 日時: 2026-09-13T01:33:43+09:00
- 判断者: ユーザー

## 目的・問題

デスクトップ版で編集直後に編集・アップロード完了ダイアログが表示される一方、アップロードされていないという報告があった。親セッションの調査では、サムネイル生成が `cannot open resource` で失敗し、編集例外が呼び出し元へ伝わらず、アップロード対象が 0 件のまま完了通知に進んでいた。

失敗を成功と誤認させないことと、次回の処理に必要な動画を残すことを目的に、編集失敗からアップロードへの境界を明示する。今回の発端となった個別導入フォントの更新時消失も、同じ再発防止パッケージの付随対象とする。

## 前提・制約

- 親セッションでは欠落フォント `ikamodoki1.ttf` の復元、ハッシュ一致、描画ライブラリによる読み込みを確認済みと報告された。実際の編集・アップロード再実行は、ユーザー承認時点では未確認である。
- `Taskfile.yml` の `build:remove-restricted` は、再配布禁止ファイルとして当該フォントを配布物から除去している。この配布除外を維持する。外部のライセンス原典は本 RECORD では確認していない。
- 部分的に編集できた動画は次回用に残す。確定済み成果物と未完成の一時成果物を区別し、既存 ADR の commit 境界と入力保全を維持する。
- ADVISE が利用上限で失敗したため、メインエージェントは契約に従ってユーザーへ直接確認し、承認を得た。

## 判断

1. 編集に失敗があれば、その実行を成功扱いにせず、アップロードへ進めない。編集・アップロードの成功通知も出さない。
2. 同じ実行内に正常に確定した編集済み動画があっても、その実行ではアップロードせず、次回用に保持する。失敗した編集の再試行に必要な入力も、既存の確定境界に従って保持する。
3. メインエージェントが選んだ具体化として、既存のグループ単位の編集継続を維持し、末尾で一般例外による失敗を集約して `RuntimeError` を呼び出し元へ伝播する。これは「最初の編集失敗で残りの編集も即停止する」という新しい方針を意味しない。
4. デスクトップ更新時は、利用者が個別導入した `assets/thumbnail/ikamodoki1.ttf` を保持する。配布物への同梱除外は継続する。

## 検討した選択肢と棄却理由

- **フォント復元だけで終了する案**: 直接の欠落は復旧できるが、次回更新での消失と、別原因の編集失敗を成功扱いにする問題が残る。ユーザーは両方の再発防止を承認した。
- **編集の一般例外を記録して正常復帰し、アップロードと完了通知へ進む既存挙動**: 今回の誤った完了表示につながったため維持しない。
- **失敗を呼び出し元へ伝え、部分的に確定した動画を次回用に残す案**: 採用。部分成果物の即時アップロードより、実行全体の失敗を正しく伝えることを優先する。
- 最初の失敗で全編集を即停止する案や、部分成功分だけを即時アップロードする案について、ユーザーとの独立した比較検討の原文はない。検討・棄却済みの判断として補わない。

## 適用範囲

- 自動・手動を含む `AutoEditor.execute` の編集失敗と、その呼び出し元でのアップロード開始・成功通知。
- 同じ実行で確定した編集済み動画の、失敗後の次回用保持。
- デスクトップ配布更新時の、指定した個別導入フォントの保持。

## 適用しない範囲

- キャンセル、成果物 commit、元録画 cleanup の既存境界の変更。
- 処理開始条件、自動再試行方針、YouTube の成否不明・重複送信保証の変更。
- 正常に処理対象が 0 件だった場合を、一律に失敗へ変更すること。
- 任意のカスタム assets の保持、フォント代替・新規同梱、一般的な更新機構への拡張。

## 期待する効果

- 編集失敗を編集・アップロード成功と誤認する通知を防ぐ。
- 部分的に確定した動画と再試行入力を失わず、次回へ引き継げる。
- 個別導入フォントの更新時消失を防ぎ、配布除外とも両立する。

## 受け入れる欠点・リスク

- 一部の編集が成功していても、失敗が残る実行ではアップロードが次回へ持ち越される。
- グループ編集は継続するため、失敗の全体通知まで残りの編集時間を要し得る。
- フォント保持は既存ファイルがある場合の保証であり、未導入状態を自動解決するものではない。
- 本記録は承認された方針の記録であり、デスクトップ実機での編集・アップロード完了の検証結果を保証しない。

## 再検討条件

ユーザーが部分成功分の即時アップロード、最初の失敗で全編集の即停止、または保持対象 assets の拡大を求めた場合に再検討する。これらは記録時に付記した見直しの目安であり、新たに承認された要件ではない。
