# macOS 初回導入を一時 VM で実検証する

- ID: 20261011-160820
- 状態: accepted
- 日時: 2026-10-11T16:08:20+09:00
- 判断者: 共同（VM 方式はユーザー、実行時の隔離・停止条件はメインエージェント）

## 目的・問題

Apple Silicon 向け macOS アプリの初回セットアップについて、Homebrew がない状態から実際の導入導線を確認します。ホストの既存ソフトウェア、設定、権限を維持する条件と、実導入を検証する必要があります。

既存の自動テストでは未導入時の案内、導入失敗、導入後の再検査を確認できますが、fake を使う境界テストだけでは Terminal や新規 macOS の初回導入を確認できません。

## 前提・制約

- ユーザーの目的は「このPCの環境は変えず」に初回導入を確認することです。ユーザーは、一時 VM のファイルと OS イメージを追加し、録画終了後に実導入を試す案を選択しました。
- この確認は Apple Silicon 上の macOS VM を対象にします。VM での成功を、実機のカメラ・USB 機器やホストの権限復旧の保証へ一般化しません。
- 質問時には空き容量が約148 GiBと報告されましたが、VM イメージ、IPSW、導入作業領域を含む容量が十分である保証ではありません。重い処理の直前に容量を再確認します。
- Homebrew 未導入からの実導入は未実行です。既存の限定テストは46件成功し、failure・error・skip は0件でしたが、導入コマンド、Terminal、macOS の権限画面を実際に通した結果ではありません。
- 既存 Homebrew、アプリケーション、OS 設定、TCC 権限、Keychain を変更しません。ホストへ新しいコンポーネントの導入や設定変更が必要になった場合は停止します。
- 録画終了後、VM の `create`・インストール・起動の直前に、録画と関連する重い処理が停止していることを再確認します。
- 実行案では、Tart の portable release archive と `TART_HOME` を今回専用の一時ディレクトリに置き、Apple の公式 IPSW から新規 VM を作ります。Tart をホストの Homebrew から導入しません。
- アプリ DMG の搬入は、今回専用ディレクトリ内の DMG 1個だけを read-only VirtioFS で共有する方式に確定しました。共有対象にリンクや他のファイルを含めず、DMG のハッシュを確認します。HOME、リポジトリ、秘密情報は共有しません。ブリッジネットワーク、外部 VNC、LAN 公開、ゲストへの SSH 導入は行いません。
- ゲストでは autologin、SSH の自動設定、sudo 認証の省略を設定しません。これらは初回導入の実体験を変えるためです。
- 実際に使う Tart release の版・SHA と署名確認結果、IPSW の版・build・取得 URL、アプリ DMG のハッシュを記録します。ダウンロード対象と容量は取得時点で確認します。
- 証拠を確保した後、今回専用の一時ファイルだけを削除します。ホストの OS ログやキャッシュを含め、完全に無痕跡となる保証はありません。

## 判断

1. macOS 初回導入を確認するため、一時 macOS VM 内で Homebrew 未導入状態からアプリのセットアップを実行し、FFmpeg、Tesseract、日本語 OCR データ、FLAC の導入と導入後の再検査を確認します。
2. ホストの既存ソフトウェア・設定・権限を変えずに、Tart、VM、OS イメージ、検証対象 DMG を今回専用の一時領域へ追加します。ホスト側の追加導入や設定変更を求められた場合は停止します。
3. すべての VM 作成・導入・起動処理は録画終了後に行い、各重処理の直前に録画と関連処理が idle であることを再確認します。
4. ゲストへの搬入には専用ディレクトリの DMG 1個だけを read-only VirtioFS で共有し、共有対象とハッシュを確認します。ブリッジネットワーク、外部 VNC、LAN 公開、ゲスト SSH、HOME・リポジトリ・秘密情報の共有は行いません。
5. 検証と証拠の確保が済んだら、今回専用の一時ファイルを削除します。

## 検討した選択肢と棄却理由

| 選択肢 | 採否と理由 |
| --- | --- |
| 既存ホストで Homebrew 未導入から実導入する | 不採用。既存の Homebrew、設定、権限を変えずに確認するというユーザーの条件に反します。 |
| 別ユーザーや一時フォルダだけを使う | 不採用。既存 Homebrew などホスト環境を分離できないため、クリーンな初回導入の確認になりません。 |
| 一時 macOS VM を使う | 採用。ユーザーがこの案を明示的に選び、ホストの既存環境を保ったまま新規 macOS 内で実導入を確認できます。 |
| 既存の fake ベースの自動テストだけで完了とする | 実導入検証の代替としては不採用。境界の確認には使えますが、実際の Homebrew 導入、Terminal、OS 権限設定は確認できません。 |
| 別のクリーンな実 Mac を使う | 現時点では不採用。助言役は理想的な候補として挙げましたが、ユーザーが一時 VM を選択しました。 |
| Apple Virtualization のサンプル等から VM 管理機構を自作する | 不採用。今回の一時検証に必要な範囲を超え、作業量と未検証部分が増えるためです。 |

## 適用範囲

- Apple Silicon 上で、アプリの macOS 初回導入を一度実検証するための環境選択と隔離条件。
- ホストにある既存の Homebrew、設定、権限を維持しながら、一時 VM 内で Homebrew とアプリ依存ソフトの導入・再検査を確認する作業。
- Tart と VM の一時ファイル、OS イメージ、検証対象 DMG の取得、証拠確保、および専用一時領域の撤去。

## 適用しない範囲

- 製品の macOS 初回導入方式、UI、Homebrew の利用方針を変更すること。
- 実機カメラ・USB 機器の列挙や接続、実機での TCC 権限拒否後の復旧を保証すること。
- ホスト OS への痕跡が一切残らないことを保証すること。
- Intel Mac、Windows、Linux、他の VM 製品に適用すること。
- 未確認の VirtioFS 共有動作を、実行済みの結果として扱うこと。

## 期待する効果

- 既存ホストのソフトウェア・設定・権限を維持しつつ、Homebrew 未導入からの実際の macOS 初回導入を確認できます。
- 既存自動テストの fake 境界で確認できたことと、新規 OS で実導入して確認できたことを区別できます。
- 実行対象の版・ハッシュ・OS build と、証拠を対応づけて残せます。

## 受け入れる欠点・リスク

- 一時ファイル、OS イメージ、仮想ディスクを追加し、ダウンロード容量と CPU・メモリを消費します。空き容量は重処理前に再確認します。
- VM が使う OS ログやホスト側キャッシュまで完全に消去できる保証はありません。
- Tart の release archive の実物の署名・ハッシュは未確認です。取得版と署名・ハッシュを実行前に確認して記録します。
- アプリ DMG だけの read-only VirtioFS 共有は計画として確定していますが、実動作は未確認です。共有範囲、リンクの有無、ハッシュが想定と異なる場合は開始しません。
- VirtioFS のためにホスト側の追加コンポーネント、システム設定変更、権限変更が必要と判明した場合は、本判断の制約に従って停止します。
- VM での成功は、実機の映像機器・音声機器、OS 権限要求・拒否・復旧が同じように動くことを証明しません。
- `main` ブランチの Tart 文書・ソースは変化する可能性があります。取得時点で再確認します。

## 再検討条件

- Tart または VirtioFS の利用に、ホストへの追加コンポーネント導入や既存設定・権限の変更が必要な場合。
- DMG 1個だけの read-only 共有を確認できない場合、または共有範囲・ハッシュが計画と異なる場合。
- IPSW、仮想ディスク、インストール作業領域を含め、ホストの残容量や録画後の idle 状態を安全に確認できない場合。
- Tart archive の版・署名・ハッシュ、IPSW の版・build・取得 URLを確認できない場合。
- 初回導入の成功判定に、実機カメラ・USB・OS 権限復旧の確認も必要だと判明した場合。その範囲は別の実機検証判断として扱います。

## ユーザー発言の原文

### 初回導入を確認したい目的と制約

> このPCの環境は変えず、初回導入の確認できない？

### 一時 VM 案への回答

受諾対象となった質問（メインエージェント）:

> 既存ソフト・設定・権限を維持したまま、一時的なmacOS仮想マシンのファイルとOSイメージを追加して、録画終了後に実際の初回導入を検証してよいですか？ 空き容量は約148 GiBあります。設計助言役の確認で、VMの保存容量・ダウンロード・実行負荷を許容するかは、今回の「環境を変えない」という条件だけでは判断できなかったため確認しています。

ユーザーの回答:

> 一時VMで実導入を検証する（推奨）

回答後のメインエージェントの確認:

> 一時VMで進めます。既存のHomebrew・設定・権限は維持し、録画が終わってからVM内で初回導入を試します。ホスト側への追加コンポーネントや設定変更が必要になった場合は、そこで止めます。
